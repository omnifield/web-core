# ❓ FAQ

Короткие ответы на конкретные вопросы, которые уже возникали по этому компоненту. Не общая
документация (она в [`README.md`](./README.md)) и не план (он в [`ROADMAP.yaml`](./ROADMAP.yaml))
— только факты, каждый проверен на практике.

---

### Почему у кита свой компонент для текста, если есть обычные `<h1>`/`<p>`/`<span>`?

**Коротко: ни Ark, ни Kobalte не дают примитива для текста — только полей ввода (`text-field`) и разметки, поэтому кит строит свой, тем же приёмом, что и `Surface`.**

Проверено: у `@ark-ui/solid` вообще нет компонента для вывода текста, у `@kobalte/core` есть только
`text-field` (поле ввода, не про вывод). Голый нативный тег работает без кита, но тогда у него нет
адреса (`data-scope`/`data-part`) — скин не может закрепить за ним правило по координате, только
голым классом снаружи.

### Почему тег (`as`) и вид (`data-variant`) — два разных выбора, а не один?

**Коротко: семантика (что это для браузера/скринридера) и внешний вид (как это выглядит) — разные решения, которые не всегда совпадают.**

`<h2 data-variant="caption">` — легальная, реальная потребность: заголовок раздела, который по
СЕО/структуре документа обязан быть `<h2>`, но визуально должен выглядеть скромно, не как большой
заголовок. Жёстко связать тег с видом (как в HTML по умолчанию `<h1>` всегда крупный) забрало бы
эту свободу — тот же довод, что уже применён к `Surface`.

### Почему обрезка (`truncated`) — настройка, а не ещё одна вариация вида?

**Коротко: обрезка перпендикулярна виду — она может понадобиться при любой вариации, и вариациями её пришлось бы дублировать на каждую.**

Ось вариаций несёт вид ЦЕЛИКОМ, поэтому «обрезанный заголовок» в ней выражается только отдельной
вариацией рядом с `heading` — а следом понадобятся такие же двойники для `body`, `caption` и для
каждого имени, которое человек заведёт в редакторе потом. Настройка печатается своим селектором
(`[data-scope="typography"][data-part="root"][data-truncated="true"]`, проверено на сгенерированном
CSS в `test/recipe.test.tsx`) и потому складывается с ЛЮБОЙ вариацией, ничего не удваивая.

В `base` рецепта это правило класть тоже нельзя: `Typography` — это и абзацы, а `white-space:
nowrap` в базе убрал бы перенос строк у всего текста кита разом.

Имя `truncated` не придумано на месте — оно добавлено в закрытый перечень имён настроек
(`SETTINGS`, `packages/skin`) отдельной заявкой, потому что своих имён настроек кит не заводит.

### Обрезка по N строк, а не по одной — почему её тут нет?

**Коротко: произвольное число строк настройкой не выражается — у настройки закрытый перечень значений, а N бесконечно.**

Флаг отвечает на «обрезать или нет», выбор (`choice`) — на «какое из ПЕРЕЧИСЛЕННЫХ значений», и
`-webkit-line-clamp: 3` в эту форму не укладывается: пришлось бы заранее выписать все N, которые
кто-нибудь когда-нибудь захочет. Механика под это другая — CSS-переменная части с `setBy` в
паспорте; заводить её раньше настоящей потребности не стали.

### Работает ли смена тега (`as`) надёжно с ЛЮБОЙ целью, не только с голым тегом?

**Коротко: нет — надёжно только с голым HTML-тегом; с другим компонентом кита в качестве цели адрес теряется, тот же предел, что у кнопки и поверхности.**

`<Typography as="h1">` — рабочий, проверенный тестом путь. `<Typography as={ДругойКомпонентКита}>`
ведёт себя иначе — адрес обёртки теряется, побеждает адрес цели. Тот же общий предел кита, что
задокументирован в `button/FAQ.md` и `surface/FAQ.md`, не особый случай этого компонента.
