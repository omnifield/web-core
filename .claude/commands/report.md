Отчёт по задаче — **комментом в узел, откуда пришло ТЗ**, а не в чат. Не дотягиваешься до
трекера — отдай текстом через user: в узел его положит architect.

До отчёта прогони проверки и возьми их фактический результат, а не ожидаемый:

```bash
pnpm lint && pnpm typecheck && pnpm test
```

Красное — так и пиши. Отчёт о работе, которая не проверена, стоит дороже отсутствия отчёта:
на нём принимают решения.

Содержание:

- **что сделано** — по существу, без парада шагов
- **что изменено** — файлы/ветка/SHA
- **чем подтверждено** — какие проверки прогнаны и с каким результатом
- **что НЕ сделано и почему** — блокеры, упёршееся, найденные чужие дефекты
- **версия пакета** — если менял поставляемое содержимое, назови, какую считаешь правильной
  (патч — правки текста и дефолтов, минор — новый артефакт или изменение состава полей).
  Сам версию не поднимаешь: это architect при публикации.

**Чужой дефект в отчёт по своей задаче не смешивай** — у смешанного перечня нет адресата,
который может его принять. Назови его отдельно, чтобы architect завёл задачу владельцу.

В чат — одна строка: отчёт положен, ключ узла, статус.

Узел: $ARGUMENTS
