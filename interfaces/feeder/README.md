<h2 id="главное">🏠 Главное</h2>

⚡ Первая сущность корня `interfaces/` — слоя между `packages/` (кирпичи) и `apps/` (поверхности):
сущность здесь сводит функционал нескольких пакетов фреймворка и накладывает на него UI, а
пользуется результатом больше чем одно приложение. `interfaces/chat` — второй ожидаемый кейс этого
же слоя, ещё не заведён.

🍽️ Feeder отвечает на один вопрос целиком: **откуда компонент берёт данные и как чужой ответ
становится его формой**. Сегодня собрана первая половина этого пути:

1. **принять описание API** — загрузить документ Swagger 2.0 или завести ручки руками, получить
   именованный пресет;
2. **показать и поправить состав** — группы, ручки, параметры;
3. **дёрнуть ручку** — форма параметров по схеме, живой HTTP-вызов, ответ наружу диспатчем.

Вторая половина — адаптер, шов между поставщиком данных и их потребителем — пока существует как
решённая модель и заготовка `entities/adapter`: форма записи в коде ещё старая. Разбор — `FAQ.md`,
раздел «Адаптер»; состояние — `ROADMAP.yaml`, `adapter-split-not-done`.

🧪 Живого браузера на текущей сборке не было — проверка только vitest+jsdom.

<h2 id="анатомия">🧩 Анатомия</h2>

🗺️ Один вход, без подпутей: `@web-core/feeder`.

| Часть | Экспортирует | Про что |
| --- | --- | --- |
| Загрузка | `ExternalSchemaLoader` | принять документ файлом или вставкой, разобрать, положить пресетом |
| Каталог | `ApiCatalog`, `Endpoints` | состав API: группы → ручки → параметры, правка состава кнопками |
| Вызов | `Endpoint`, `Call`, `useInvoke`, `invokeEndpoint` | форма параметров, один HTTP-вызов, ответ |
| Склад | `presetsStore`, `Presets`, `PresetInfo` | именованные пользовательские записи, отбор по виду |
| Модель API | `API_KIND`, `parseSchema`, `asSchemaDocument`, `endpointOf`, `groupEndpoints`, `schemaNodeToZod` | наш формат документа и работа с ним |
| Форма | `TreeForm` | дерево по произвольной зод-схеме |
| Адаптер | `applyAdapter`, `adapterStoreOf`, `adapterBy`, `sourceKey`, `isFed`, `noFeed` | заготовка шва, UI ещё нет |
| Типы | `Preset`, `PresetsState`, `SchemaDocument`, `SchemaNode`, `EndpointDescriptor`, `EndpointParam`, `Group`, `EndpointGroup`, `HttpMethod`, `ParamIn`, `OpenapiEndpoint`, `InvokeResult`, `Invocation`, `ApiCatalogResult`, `Adapter`, `AdaptersState`, `FeedSource`, `Consumer` | |

📦 Внутри — адаптированный FSD, переосмысленный под движок (правила слоёв — [`src/DBP.md`](./src/DBP.md)):

- `entities/preset` — склад: `Preset { id, kind, name, content }`, стор и механика показа записей
  своего вида. Про содержимое `content` не знает ничего, а `kind` сравнивает, но не толкует;
- `entities/openapi` — наш формат API: `SchemaDocument { endpoints, groups, defs }`, распознавание
  Swagger 2.0 (`swagger2Template` поверх `@web-core/generators/mapping`), простановка айди ручкам
  и сборка групп из тегов документа (`identify`), JSON Schema → zod (`schemaNodeToZod`),
  компоновка ручек по группам, правки состава, примитивы вызова;
- `entities/form` — движок дерева по зод-схеме (`Tree`, `useTree`, `itemBinding`, kit инпутов);
- `entities/adapter` — заготовка шва «поставщик → потребитель»: тип, стор, `applyAdapter` поверх
  `@web-core/io`. Ни один экран его сегодня не зовёт;
- `features/external-schema` — экран загрузки документа;
- `features/api-manager` — каталог пресетов-схем (`ApiCatalog`) и узел ручки (`Endpoint` = форма
  настройки `Config` + вызов `Call`);
- `features/tree-form` — `TreeForm`, интерфейсная обёртка над `entities/form`;
- `shared/ui` — обвязка без знания о предмете: `Box` (аккордеон-узел со своими действиями, на нём
  стоят и каталог, и списки формы) и `RawLoader` (файл или вставка → сырой текст, надпись и
  `accept` пропами). Наружу пакета не отдаётся.

Почему склад не знает про ручки, а `entities/openapi` — про склад: это два независимых предмета,
и сводит их фича. Разбор — `FAQ.md`, «Пресет как склад».

<h2 id="использование">🚀 Использование</h2>

✅ Экран настройки API — два компонента:

```tsx
import { ApiCatalog, ExternalSchemaLoader } from "@web-core/feeder";

<>
  <ExternalSchemaLoader />
  <ApiCatalog onResult={(event) => setProbe(event)} />
</>;
```

Связывать их не нужно — оба ходят в модульный стор пресетов. `onResult` необязателен: он нужен
тому, кто собирается что-то делать с ответом (снять с него форму, показать рядом), а не самому
каталогу.

✅ Пресет без загрузчика:

```ts
import { API_KIND, parseSchema, presetsStore } from "@web-core/feeder";

presetsStore.actions.add(API_KIND, "petstore", await parseSchema(rawSwaggerText));
```

Вид (`kind`) ставит тот, кто завозит запись: по нему каталог её и находит. Запись без вида `api`
он не покажет и ругаться на неё не станет — она не его.

✅ Вызов ручки кодом:

```ts
import { endpointOf, invokeEndpoint } from "@web-core/feeder";

const result = await invokeEndpoint(endpointOf(descriptor, document.defs), { id: 7 });
```

✅ Форма по любой зод-схеме:

```tsx
import { TreeForm } from "@web-core/feeder";

<TreeForm schema={schema} value={value()} onChange={setValue} />;
```

Все сценарии по шагам — [`EXAMPLES.md`](./EXAMPLES.md): свой экран вместо `ApiCatalog`, точечная
правка состава, сохранение пресетов наружу, форма параметров своими руками, таблица «документ не
распознался — где смотреть».

<h2 id="настройки">🎚️ Настройки</h2>

🔧 `ExternalSchemaLoader` — **без пропов**: работает с общим стором пресетов. `ApiCatalog`
оттуда же берёт состав и принимает один необязательный проп — `onResult`. Это диспатч ответа
наружу: каждый удавшийся вызов ручки из каталога приезжает в него
`ApiCatalogResult { presetId, endpoint, result }`. Не передали — ответ просто никуда не идёт.

Состав каталог правит сам, через склад: «+» на схеме заводит пустую группу, «+» на группе —
пустую ручку под ней, корзина убирает схему, группу (со всеми её ручками) или одну ручку. У самой
ручки «+» нет — глубже заводить нечего. Новая запись встаёт первой; ручка — первой в своей группе.

`Endpoints` — `document: SchemaDocument` (документ целиком: реестр групп лежит в нём, и без него
пустую группу нечем показать), необязательный `label` (заголовок верхней секции) и набор колбэков:
`onAddGroup`, `onRemove`, `onAddEndpoint(group)`, `onRemoveGroup(group)`, `onRemoveEndpoint(endpoint)`.
Кнопки появляются **от самого колбэка** — не передали, кнопки нет. `children` — что монтируется
внутрь ручки; принимает **аксессор**, не значение.

`Presets` — механика склада: `kind` (вид записей), `as` (страж содержимого), необязательные
`empty`/`broken` (тексты пустого списка и битой записи) и обязательный `children`. В `children`
приезжают три вещи: аксессор записи, аксессор **уже приведённого** стражем содержимого и правка
черновиком по этой записи — `presetsStore.actions.edit` потребитель не зовёт. Карточку список не
навязывает: вид узла решает тот, кто монтирует.

`Endpoint` — `endpoint: EndpointDescriptor`, `defs`, необязательный `onResult`; внутри держит
значение параметров и собирает форму с вызовом. `Call` — `endpoint: OpenapiEndpoint`, `value`,
необязательный `onResult`: только дёрнуть и сказать, если не дошло.

`PresetInfo` — `name` / `onName`.

`TreeForm` — `schema: z.ZodType`, `value`, `onChange`.

Чего у движка **нет**: форматов кроме Swagger 2.0; заголовков и авторизации у вызова; UI сведения
полей; хранения между сессиями. Заведённую ручку пока **нечем заполнить**, а группу — **нечем
переименовать**: правки полей на экране нет, только черновиком из кода.

<h2 id="состояния">🎛️ Состояния</h2>

🚦 Пакет держит одно живое состояние в сторе, остальное контролируется снаружи.

- `presetsStore` — `{ presets: Preset[] }`, модульный синглтон (`createActionStore`
  из `@web-core/store`). Действия: `add(kind, name, content) → id`, `remove(id)`,
  `rename(id, name)`, `replace(id, content)`, `edit<T>(id, recipe)` (immer-черновик содержимого),
  `hydrate(presets)`. Селекторы `presetBy(id)` и `presetsOf(kind)` — оба реактивные. Айди — uuid
  при создании, и он не зависит ни от имени, ни от вида, ни от содержимого;
- `adapterStoreOf(key)` — семья сторов адаптеров, заготовка: живого потребителя нет.

Локальное состояние сборки: `Endpoint` держит значение параметров (его читают и форма, и вызов),
`Call` — результат и отказ своего вызова, `ExternalSchemaLoader` — имя будущего пресета и текст
ошибки разбора.

<h2 id="io">🔌 IO</h2>

↔️ **Загрузка.** Вход — сырой текст документа. `parseSchema(raw)` прогоняет его через шаблоны
(сегодня один, Swagger 2.0, совпадение жёсткое), выдаёт айди ручкам, превращает теги документа в
группы и отдаёт `SchemaDocument`. Нераспознанный документ — исключение, экран показывает его
текстом.

↔️ **Документ.** `SchemaDocument { endpoints, groups, defs }`; ручка —
`{ id, method, url, groupId?, params }`, группа — `{ id, name }`, где `params[].schema` — JSON
Schema, а `defs` держит общие типы (`$ref` остаются ссылками, циклы не разворачиваются). Чистый
JSON: сериализуется и уезжает на склад как есть. Зод строится из формата при отрисовке
(`endpointOf`) и нигде не хранится.

↔️ **Айди ручки и группы.** Уникальные, выдаются при разборе и ни от чего не производны. Ими
записи опознаются в списках и в правках состава: метод, урл и имя группы юзер правит, и тождество
на них не держится. Документ без айди у ручки схемой не признаётся (`asSchemaDocument` вернёт
`undefined`) — единственное место, где айди проставляются, это входной слой.

↔️ **Компоновка.** `groupEndpoints(document)` собирает ручки по `groupId` в порядке реестра групп —
включая пустые группы, у них своя запись. Ручки без `groupId` и ручки со ссылкой в никуда уходят в
псевдогруппу `unknown`, она всегда последняя. `unknown` — не запись и в документе не лежит.
`groups` в документе необязателен: нет поля — читаем как пустой реестр.

↔️ **Склад.** `Preset { id, kind, name, content }`, `content` непрозрачен. `kind` — ярлык вида
(`api` у документа схемы), который ставит дверь при заведении записи; склад его сравнивает, а не
толкует, и по нему же отбирает записи (`presetsOf`). `hydrate` заменяет состав целиком.

↔️ **Вызов.** `invokeEndpoint(endpoint, value)` → `InvokeResult { status, ok, headers, body }`.
Имя, встреченное в `{плейсхолдере}` url, уходит в путь; ключ `body` — в JSON-тело; остальное — в
query. **Не-2xx — валидный результат**, а сорванный транспорт — исключение: ответа не было вовсе.
`useInvoke` это исключение ловит и кладёт текст в `failure()`.

↔️ **Диспатч ответа.** Каталог сам ответ не показывает и не хранит — отдаёт наружу
`ApiCatalogResult { presetId, endpoint, result }`. Ответ без указания, чей он, снаружи
бесполезен: на экране ручек много. Сорванный вызов наружу не уходит вовсе — `Call`
называет его словами у себя, отдавать нечего.

<h2 id="сборки">🏗️ Сборки</h2>

🧪 Vitest + jsdom. **143 теста, все зелёные:**

- `entities/openapi` — распознавание petstore и превращение его тегов в группы, айди ручкам при
  разборе (уникальны, не производны от содержимого), JSON Schema → zod (вложенные `$ref`, циклы
  через `z.lazy`), дескриптор → ручка, компоновка по группам (порядок реестра, пустая группа,
  ссылка в никуда), правки состава (заведение группы и пустой ручки, удаление ручки и группы со
  всем содержимым), живучесть узлов при правке урла и при переименовании группы;
- `entities/preset` — стор (добавить/убрать/переименовать/заменить/править черновиком/поднять,
  вид записи и отбор по нему), механика показа в настоящем DOM: отбор своего вида, пустое
  состояние текстом потребителя, приведённое стражем содержимое наружу, правка черновиком из
  узла доезжает в стор, живучесть узла при переименовании;
- `entities/form` — `itemBinding`/`useTree` чистой логикой и `Tree` смонтированным по-настоящему;
- `entities/adapter` — `applyAdapter` на наборе записей и на одиночном объекте, все именные отказы,
  стор;
- `features/api-manager` — вызов на моке `fetch` (путь/квери/тело, 404 как результат, TypeError как
  исключение), `useInvoke`, каталог схем в DOM, диспатч ответа наружу — в событии тот пресет и та
  ручка, по которой ткнули, — и правка состава кнопками каталога (группа, ручка в группе, удаление
  на всех трёх уровнях);
- `features/external-schema` — сквозной путь «вставили документ → в сторе лежит разобранный пресет»;
- `shared` — `Box`: кнопки от колбэков, действие отдаёт элемент, верхняя секция от `label`;
  `RawLoader`: вставка уходит наружу как есть, надпись кнопки от потребителя, запрет снаружи
  держит кнопку закрытой, сам ничего не хранит.

`lint` и `typecheck` зелёные.

Ark-UI/Zag/Kobalte внутри `@web-core/ui` отдают сырой `.jsx` по `solid`-condition — vitest грузит
его напрямую через Node и падает; лечится `test.server.deps.inline` в `vitest.config.ts`.

<h2 id="рецепт">🎨 Рецепт</h2>

🧩 Четыре приёма, которые стоит понять, чтобы не спорить с движком:

**Чужой формат разбирается один раз, на входе.** После импорта нет ни Swagger 2.0, ни любого
другого — есть наш документ. Иначе каждая манипуляция начиналась бы с вопроса «а что это за формат
и как его читать», и так на сто форматов вперёд. Поэтому сырьё не хранится, а правка ручки не
упирается в сериализацию чужой спеки.

**Склад не знает, что на нём лежит, но знает, чего оно вида.** `Preset` — имя плюс непрозрачное
содержимое плюс ярлык вида, который склад сравнивает строкой и не толкует. Поэтому потребителей
может быть много (сегодня документ API, завтра адаптер), и каждый находит свои записи, не заглядывая
в чужие. Перебор, страж и правка черновиком при этом тоже механика склада, а не экрана: экран
говорит, какой вид ему нужен, чем приводить содержимое и что рисовать в узле.

**Тождество узла — по выданному айди, а не по ссылке и не по содержимому.** Состояние живёт в DOM
(открытость аккордеона, фокус, ввод), а иммутабельный стор отдаёт новый объект на каждую правку.
Поэтому списки перебираются `<Key by>`, а тела списков принимают аксессор, а не значение: узел
остаётся тем же, меняется то, что он показывает. Ключ при этом обязан быть выданным, а не
собранным из полей: метод, урл и имя группы правит юзер, и ключ на них разъезжается с сущностью.
Разбор — `FAQ.md`, «Списки и тождество узла».

**Группа — запись, а не свойство ручки.** Она лежит в документе своей строкой `{ id, name }`, и
ручка ссылается на неё айди. Поэтому имя правится без последствий, пустая группа законна, а две
группы с одинаковым именем остаются двумя разными. Тег из чужого документа живёт ровно до входной
двери: `identify` превращает его в группу и дальше слова «тег» в пакете нет.

Вся механика описания форм и применения правил — в `@web-core/io`. Feeder не пишет своего движка
сведения: он даёт интерфейс и решает, что и в каком порядке спросить у человека.
