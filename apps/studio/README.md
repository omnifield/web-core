<h2 id="главное">🏠 Главное</h2>

🖼️ Живая витрина кита `@web-core/ui`: компонент виден настоящим рендером через настоящий движок
сборки (`@web-core/assembly`) — тем же путём, каким его получает любой продукт, а не макетом и не
скриншотом. 🔢 Показывается не один экземпляр, а всё поле сразу: компонент умножается по двум осям
— варианты наряда и сборки, — и обе раскладки рисуют одно и то же пересечение, отличаясь лишь
подачей.

🍽️ Данные для показа приходят со стороны: компонент **кормят**, и чем именно — решает не показ.
Сохранённая запись, форма с ручным вводом, завтра ручка чужого API — это сменные поставщики, а
не части витрины. 🧪 Рядом с витриной — лаборатория (`/lab`), где компонент не смотрят, а собирают.

<h2 id="анатомия">🧩 Анатомия</h2>

🗺️ У приложения нет импортируемой поверхности — «часть» здесь означает маршрут, а «адрес» — URL,
по которому эта часть открывается. Карта маршрутов собирается не файловой раскладкой, а явным
списком (`shared/configs/routes.config.ts`).

| Часть            | Адрес                            | Показывает                                                    |
| ---------------- | -------------------------------- | ------------------------------------------------------------- |
| Витрина          | `/showcase/{-$component}`        | поле показа выбранного компонента плюс правый рейл управления  |
| Лаборатория      | `/lab/{-$component}/{-$feature}` | рабочее место сборки; правый рейл переключается по `feature`   |
| Песочница        | `/playground`                    | дерево кита без правой панели                                  |
| Изолированный показ | `/embed/$component/$assembly` | показ без хрома — для агента через MCP-браузер (сейчас заглушка) |

🧱 Первые три части живут под общим хромом (`pages/route.tsx` — шапка и рабочая область);
`/embed` висит отдельно прямо под корнем и хрома не наследует намеренно.

📦 Внутри — слои FSD, у каждой папки ровно один публичный вход, снаружи не видно ничего глубже:

| Слой        | Что там                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| `app/`      | точка входа и провайдеры: `mountApp`, роутер, кэш запросов, скин                                       |
| `pages/`    | раскладка воркспейса и сами экраны — **место сборки виджетов**                                          |
| `widgets/`  | `preview` (область показа и переключатели), `feed` (панель поставщиков), `rail` (поверхность рейла и её секции), `catalogs`, `navigations`, `header`, `docs`, `chat` |
| `features/` | `preview` (механика показа: оси, ячейки, раскладки, виды), `feed/preset`, `feed/manual`, `feed/openapi` (поставщики еды), `settings` (панель настроек компонента), `api-setup` (загрузка схем и каталог ручек) |
| `entities/` | `component` (что это за компонент), `feed` (чем он накормлен), `settings` (чем он настроен), `endpoint` (какую ручку дёрнули), `user` |
| `shared/`   | клиенты служб, карта маршрутов, `renderer`, плоскость матрицы, переключатель темы                       |

🔌 Виджет называет МЕСТО или ТЕМУ, а не хозяина, и `rail`/`catalogs`/`navigations`/`header` не
знают ни одной фичи и ни одной сущности этого приложения — им предстоит уехать в общий пакет.

<h2 id="использование">🚀 Использование</h2>

✅ Три сценария покрывают то, чем реально пользуются: поднять витрину, открыть компонент, накормить
его своими данными из кода.

**Поднять витрину:**

```sh
pnpm --filter @web-core/studio dev
# http://localhost:5174/showcase
```

**Открыть компонент напрямую** (или кликом по дереву слева — оно ведёт туда же):

```
http://localhost:5174/showcase/button
```

**Прочитать и положить еду из любого места под компонентом** (`entities/feed`):

```ts
import { useFeed } from "#/entities/feed";

const feed = useFeed();

feed.serve("preset", { label: "Сохранить" }); // положить: метка + данные
feed.data(); // прочитать: то, что лежит сейчас
feed.servedBy(); // "preset" — кто положил
```

<h2 id="настройки">🎚️ Настройки</h2>

🔧 Настраивает витрину окружение Vite и флаги запуска — отдельной сущности с общим списком нет.
🎚️ Настройки ПОКАЗЫВАЕМОГО компонента — другая ось: их объявляет его паспорт (`orientation`,
`multiple` и прочие), витрина показывает объявленное секцией рейла и ничего к списку не добавляет.
Переменные читаются `fromEnv` (`@web-core/build/env`), поэтому у каждой работает и голое имя, и
`VITE_`-форма; файл окружения лежит в КОРНЕ воркспейса, не в папке приложения.

| Настройка        | Где                          | По умолчанию                          |
| ---------------- | ---------------------------- | ------------------------------------- |
| `PRESETS_URL`    | `shared/api/clients`         | `http://127.0.0.1:8787` (+ `/graphql` дописывается сам) |
| `VITE_DOCS_URL`  | `shared/configs/urls.ts`     | `http://localhost:7777/workspaces/UI/pages` |
| `NEUROBOX_URL`   | `shared/api/clients`         | нет — без него чат не с кем вести      |
| `NEUROBOX_TOKEN` | `shared/api/clients`         | пусто                                  |
| `NEUROBOX_USER`  | `shared/api/clients`         | `studio-lab`                           |
| `--port`         | `package.json`, флаг Vite    | `5174` (`--strictPort` — второй не встанет тихо на соседний) |
| `--host`         | `package.json`, флаг Vite    | `0.0.0.0`                              |

<h2 id="состояния">🎛️ Состояния</h2>

🚦 Ловимых состояний два набора, и оба живут в сущностях, а не в экранах.

| Состояние            | Метка                          | Где                    |
| -------------------- | ------------------------------ | ---------------------- |
| Данные компонента едут | `isPending()`                  | `useComponent()`       |
| Служба отказала       | `error()`                      | `useComponent()`       |
| Компонент накормлен   | `servedBy()` — метка поставщика | `useFeed()`            |
| Еды нет вовсе         | `data()` — `undefined`          | `useFeed()`            |
| Настройка отменена зависимостью | `applies` на самой настройке | `useSettings()` |

⚡ Синхронная часть сведений о компоненте (срез редактора, io-схема) доступна и в `isPending`:
она берётся из кита напрямую, по сети едет только то, что лежит в службе пресетов.

<h2 id="io">🔌 IO</h2>

↔️ Вход — параметры маршрута и две сетевые службы; выход — настоящий DOM компонента.

### 📥 Вход

| Источник               | Форма                                                          |
| ---------------------- | ---------------------------------------------------------------- |
| Параметры маршрута     | `{ component?: string, feature?: string, assembly?: string }`     |
| Служба пресетов        | GraphQL: варианты, сборки, записи данных, наряды, палитры, теги   |
| Neurobox               | поток и прогоны агента для чата лаборатории                       |
| Кит `@web-core/ui`     | список компонентов, паспорт, io-схема — синхронно, без сети       |

### 📤 Выход

| Источник                | Отдаёт                                                     |
| ----------------------- | ------------------------------------------------------------ |
| `Renderer` (`RenderTree`) | реальный DOM компонента — тем же движком, что у продукта     |
| `entities/feed`          | текущую порцию еды всем, кто её спросит                      |

<h2 id="сборки">🏗️ Сборки</h2>

🧪 Проверок две породы, и они не заменяют друг друга: прогон держит механику, браузер —
то, что видно глазом.

| Композиция                                              | Чем доказана                                                    |
| ------------------------------------------------------- | ----------------------------------------------------------------- |
| Доска кормления берёт еду себе и не морозит чужое        | `test/feed-board.test.ts`                                          |
| Разрешение «ячейка → показанный элемент», адресация scope | `test/preview-secondary.test.ts`                                   |
| Группировка оси и применимость фильтра                   | `test/preview-grouping.test.ts`                                    |
| Арифметика и монтирование плоскости матрицы              | `test/plane-position.test.ts`, `test/plane-mount-scroll.test.tsx`   |
| Реактивность дерева рендера на смену данных              | `test/render-tree-*.test.tsx`, `test/select-incremental-growth.test.tsx` |
| Настройки паспорта: список, умолчания, зависимость       | `test/component-settings.test.ts`                                  |
| Поставщик → доска → показ, в обе стороны                 | живой прогон в браузере: выбор записи меняет все ячейки, правка формой доезжает туда же |
| Настройка → доска → корневые пропы показа                | живой прогон: `orientation` развернул все семь ячеек, `multiple` дал держать два раздела открытыми |
| Ручка API → адаптер → доска → показ                      | сквозной живой прогон: схема, вызов, сведение полей мышью, вызов с витрины — записи ответа доехали до всех ячеек |

<h2 id="рецепт">🎨 Рецепт</h2>

🍽️ Съёмный слой этого приложения — **поставщики еды**. Доска (`entities/feed`) объявляет контракт
и ничего не знает о том, кто её наполняет; воплощения живут СНАРУЖИ неё, каждое своей фичей под
`features/feed/`.

```ts
// features/feed/<поставщик>/ui.tsx
const feed = useFeed();
feed.serve("preset", record.state.data); // метка — открытая строка, не перечисление
```

🔌 Третий поставщик — живая ручка API: связь «ручка ↔ компонент» собирается в лаборатории
(`/lab`), а витрина показывает только те ручки, у которых связь с этим компонентом есть, и
кормит уже собранной едой. Механику связи целиком держит `@web-core/feeder`; студия называет ему
участников и кладёт результат на доску.

✨ Поставщик держит СВОЁ состояние у себя (какая запись выбрана, черновик формы, адрес ручки) —
на доске лежит только еда и метка. Поэтому соседи друг о друге не знают: чужую подачу поставщик
не перебивает, проверяя не имя соседа, а факт «положил не я». Новый поставщик — новая папка,
строка в панели (`widgets/feed`'s `FeedPanel`) и строка импорта; ни доска, ни показ при этом не
меняются. Все поставщики стоят в одной секции рейла — «Данные», — разделённые чертой.
