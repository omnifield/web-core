# `pages` — экраны приложения

## Место в иерархии

Порядок слоёв сверху вниз: `app → routes → pages → widgets → features → entities → shared`.
`pages` — второй сверху: выше него только `routes`/`app`; ниже — `widgets`, `features`,
`entities`, `shared`.

## Что кладётся в `pages`

Слой композиции: собирает `widgets` + `features` + `entities` + `shared` в готовый экран
целиком. Здесь и ТОЛЬКО здесь можно связать между собой несколько виджетов — страница
импортирует нужные виджеты и передаёт им общее состояние (например, чтобы один виджет
реагировал на выбор, сделанный в другом). Виджетам самим об этом соседстве знать не положено
(см. [`../widgets/DBP.md`](../widgets/DBP.md)) — это ровно та работа, ради которой существует
отдельный слой `pages`. Страница может монтировать и отдельную фичу напрямую (см.
[`../features/DBP.md`](../features/DBP.md)), минуя виджет, если действию не нужен целый блок
интерфейса вокруг себя.

## Правило импортов

- `pages` импортирует из `widgets`, `features`, `entities`, `shared`.
- НЕ импортирует `routes`/`app` — страница не знает, по какому URL и через какой роутер её
  открыли. Параметры страницы приходят как пропсы или читаются из сущности/атома, а не
  завязаны на устройство роутера внутри самой страницы, там где этого можно избежать.

## Тяжёлая логика — не сюда

Страница — это композиция (собрать `widgets`/`features` вместе) и лёгкие хуки (прочитать
параметр, локальный сигнал для UI-состояния). Запросы, которые должны ЗАБЛОКИРОВАТЬ переход,
пока данные не готовы — не здесь: это `loader` в соответствующем `route.tsx`, см.
[`../routes/DBP.md`](../routes/DBP.md). Если код страницы начинает следить за `isLoading` и
руками решать, что показать вместо контента, пока грузится — это симптом, что логика заехала
не на тот уровень.
- Страницы друг друга не импортируют. Каждая страница независима; если двум экранам нужен
  общий кусок разметки — он выносится в `widgets` (если это самостоятельный блок с данными)
  или `shared/ui` (если это чистый визуальный примитив), а не шарится прямым импортом одной
  страницы в другую.

## Слайсы

Каждый слайс — один экран приложения, к которому ведёт один или несколько маршрутов из
`routes`. Слайс может быть как самостоятельным файлом, так и общим layout-каркасом для
нескольких вложенных маршрутов — оба варианта нормальны, пока каждый отвечает ровно за один
экран/каркас, а не за несколько разных не связанных друг с другом.

## Почему это разделение важно

Тот же принцип, что и на нижних слоях: `pages` — единственное место, где допустима связь
между виджетами, потому что связывание нескольких независимых блоков в один экран — это ЗАДАЧА
экрана, а не задача самих блоков. Если логику межвиджетовой связи размазать по самим виджетам,
теряется возможность переиспользовать виджет на другом экране без хвоста чужих зависимостей.
