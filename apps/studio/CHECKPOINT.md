
Тесты: логин заводит сессию и кладёт id рядом · чат ходит с сохранённым id и второй сессии не
заводит · 404 → стор заводит новую, сообщение не теряется · обрыв потока → дочитывание · выход
чистит логин и сессию · не залогинен → запроса нет вовсе.

Тест поймал настоящий баг, починенный в коде: логин кириллицей нельзя положить в `X-User-Login` —
HTTP-заголовок это байты (ISO-8859-1), `fetch` роняет запрос ещё до сети. Не-ASCII логин едет
процентно закодированным.

## ❗ Открытые вопросы (не наши решения)

- **Живой проверки нет** — нужен адрес бокса и `VITE_CHAT_TOKEN`.
- **Сессия теперь одна на юзера, не на компонент.** По ТЗ так и просили, но у бокса одна сессия =
  одна память и один счёт, и агент перечитывает всю историю на каждом ходу — со временем разговор
  дорожает. Понадобится дешевле — резать сессию по компоненту (id тогда не один, а таблица).
- **Читаемость логина для бокса** — кириллица доезжает как `%D0%B5%D0%B2%D0%B0`. Нужен читаемый —
  ограничивать логин латиницей на форме входа.
- **Пароль формы входа захардкожен** (`PASSWORD = "123"`) и не связан с `VITE_CHAT_TOKEN`.
- **История чата при заходе не грузится**, `did`/`means` в UI не рендерятся, отмена прогона
  (`POST /runs/{run}/cancel`) не подключена, `variant`/`outfit` в `context` не шлём.
