<h2 id="главное">🏠 Главное</h2>

🖥️ Конечные поверхности: то, что открывают в браузере по адресу, а не импортируют как пакет.
Каждое приложение — обычный Vite-проект на оснастке [`@web-core/build`](../web-core/build/README.md),
без самописной обвязки: три конфига по три строки и `mountApp()` в `#root`.

🎯 Приложения здесь существуют, чтобы **что-то доказывать про фреймворк**, а не чтобы обслуживать
пользователя: витрина показывает кит настоящим рендером, эталон падает при сломанном шве между
зонами, демо-дашборд доказывает, что собранное в студии живёт там, где студии нет. Продукт,
который решает задачу заказчика, — это `../products/`, не здесь.

<h2 id="критерий">🚪 Критерий включения</h2>

✅ **Сюда кладут** поверхность, у которой:

1. **адрес, а не импорт-путь** — её часть это маршрут (URL), а не экспорт пакета;
2. **своя точка входа и свой порт** — приложение поднимается само, а не встраивается в чужое;
3. **предмет — сам фреймворк** — оно показывает, проверяет или демонстрирует базу, а не ведёт
   бизнес-логику заказчика.

🚫 **Сюда НЕ кладут:**

- **механизм для импорта** — это `../web-core/` (публикуемая поверхность) или `../interfaces/`
  (готовый UI из нескольких пакетов);
- **продукт со своей предметной областью** — это `../products/`, оттуда он уедет своим
  репозиторием;
- **службу со своим сетевым контрактом** — это `../backend/`.

витрины.

<h2 id="правила">📏 Общие правила группы</h2>

- 🚫 **Не публикуются.** `"private": true`, версии нет, в `versioning.fixed` не входят —
  приложение доказывает, а не поставляется. Поэтому же они перечислены в `versioning.ignore`
  (`../pnpm-workspace.yaml`): иначе висели бы в плане выпуска строками `0.0.0 → 0.0.0`.
- 🔌 **Пакеты берут НОМЕРОМ ВЕРСИИ** (`"@web-core/ui": "^0.4.0"`), а не протоколом `workspace:*`.
  Приложение обязано собираться и в одиночку: клонировали только его — база встала из реестра.
  `workspace:*` этого не умеет в принципе, вне воркспейса он не разрешается вовсе. Когда пакеты
  лежат рядом, та же строка даёт живую папку: подстановку по диапазону включает
  `linkWorkspacePackages` (`../pnpm-workspace.yaml`), и правка в пакете видна сразу, без выпуска.
- 🔢 **Свой порт с `--strictPort`** — чтобы приложения жили рядом и второе не встало молча на
  соседний порт, притворившись первым.
- 🧾 **Своя тройка доков** по шаблону `genus: app` (пилот — [`studio`](./studio/README.md)): у
  приложения «часть» означает маршрут, а «адрес» — URL, не импорт-путь и не CSS-селектор.
- 🧪 **Проверки зелёные перед коммитом**: `pnpm --filter @web-core/<приложение> lint typecheck test`.
- 🧰 **Новых механик не заводят.** Понадобилась механика, которой нет в базе — это заявка
  владельцу соответствующего пакета, а не код в приложении: иначе фреймворк доказывает себя
  тем, чего в нём нет.

<h2 id="новое">➕ Как завести новое приложение</h2>

1. Проверить по [критерию включения](#критерий), что это правда поверхность-доказательство, а не
   продукт и не пакет.
2. Завести папку, `package.json` с `"private": true`, три конфига из
   [`build`](../web-core/build/README.md), монтирование через `mountApp()`
   (`@web-core/solid`).
3. Выбрать свободный порт и зафиксировать `--strictPort`; назвать порт в своём README.
4. Вписать путь приложения в `versioning.ignore` (`../pnpm-workspace.yaml`) — оно не участвует в
   выпуске.
5. Завести зону владельца в `../.claude/harness.yaml`.
6. Написать тройку доков по факту кода и добавить строку в [состав](#состав) этого файла.
