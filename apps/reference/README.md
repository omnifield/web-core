# `reference` — эталонное приложение web-core

**Это гейт сборки цепочки, а не витрина.** Его работа — падать, когда сломан шов между зонами.
Красивое приложение, которое поломку не ловит, здесь бесполезно; маленькое и злое — полезно.

Приватное: в реестр не едет, версии не имеет (`"private": true`). Контракт зон, поверхность
которого оно потребляет, описан ниже — в разделе «Что именно ломается, если сломать шов».

## Запуск

```bash
pnpm install     # связи на пакеты — `workspace:*`
pnpm dev         # живая страница
pnpm build       # сборка конфигом из зоны `build`
pnpm test        # 39 проверок: поведение, сборка, дев-сервер, оснастка, поставки, шов со скином
pnpm lint        # пресет `@web-core/lint` + `tsc --noEmit`
```

Пакеты подключены **воркспейсом**, а не из реестра: выпуск ещё не опубликован, а ждать
публикации ради проверки значило бы её не делать. `workspace:*` кладёт симлинк — **свежесть
соседа видна сразу**, пересобранный `dist` доезжает сюда без переустановки.

## Что внутри

| файл | зачем |
|---|---|
| `index.html` | точка монтирования `#root` — часть замороженной поверхности |
| `src/main.tsx` | вход: один CSS-подпуть, надевание скина, `mount()` — состав как в скелете |
| `src/app.tsx` | единственный экран: форма «заявка» на всей цепочке |
| `src/skin.ts` | СКИН страницы: семя скруглений, имена для оформления, рецепт кнопки |
| `src/app.css` | раскладка ПОТРЕБИТЕЛЯ: только `data-slot` и ИМЕНА СКИНА, без цвета |
| `src/trace.ts` | perf-канал приложения, флаг `__WEB_CORE_REFERENCE_TRACE__` |
| `vite.config.ts` · `vitest.config.ts` · `tsconfig.json` | три строки: взять оснастку из зоны `build` |

Экран намеренно один. Полигон, выросший в приложение, перестаёт быть полигоном: за ним
начинают ухаживать вместо того, чтобы им проверять.

## Что именно ломается, если сломать шов

Четыре замороженные точки поверхности — четыре ответа, и пятым идёт скин: он поверхность не
замораживает, но вид страницы приходит только им. В каждом названо, **что увидит человек** и
**какая проверка покраснеет**: гейт стоит ровно там, где поломка иначе прошла бы молча.

### 1. Рантайм — `mount()` и `#root`

Сломать можно двумя способами, и оба тихие.

- **Переименовали идентификатор точки монтирования** (в рантайме или в нашем `index.html`) —
  компилятор молчит (типы про разметку не знают), линтер молчит, `vite build` зелёный,
  **страница пустая**. Краснеет: `test/mount.test.tsx` — «без `#root` падает внятно», и
  `test/chain.test.ts` — «после исполнения бандла в `#root` стоит живой кит».
- **`mount()` перестал держать владение** (выбросили `dispose`, второй корень лёг сверху
  первого) — страница выглядит правильной, а вычисления первого корня остаются живыми.
  Это предмет тестов зоны `runtime`; здесь проверяется связка «разметка ↔ рантайм»: точку
  монтирования приложение не передаёт и знать о ней не обязано.

### 2. Сборка — `/vite`, `/tsconfig`, `/vitest`

- **Из конфига Vite пропал solid-плагин** — сборка падает на первом же JSX, а если и соберётся,
  в `#root` не появится ни одного узла. Краснеет: `test/chain.test.ts` (сборка отдельным
  процессом, как у потребителя) и `test/dev.test.ts` (в деве вход приезжает преобразованным).
- **Из пресета vitest ушло `resolve.conditions`** — `solid-js/web` разрешается в СЕРВЕРНУЮ
  ветку, и весь DOM-прогон падает с «Client-only API called on the server side». Краснеет всё
  разом: это ровно то, ради чего условие в пресете и стоит.
- **Из базового `tsconfig` уехал `jsxImportSource`** — `pnpm lint` красный, потому что
  `tsconfig.json` приложения не содержит своих `compilerOptions` и починить это у себя нельзя.
- **Оснастку «починили» на месте** — дописали плагин в `vite.config.ts`, условие в
  `vitest.config.ts`, опцию в `tsconfig.json`. Приложение после этого собирается ЧЕМ УГОДНО и
  перестаёт быть гейтом навсегда, оставаясь зелёным. Краснеет: `test/gate.test.ts` — он сверяет
  конфиги приложения с тем, что отдаёт зона `build`, и стережёт отсутствие `compilerOptions`.

### 3. Кит — `@web-core/ui`

- **Пропала зацепка `data-slot`** — вся страница осядет без раскладки: `app.css` цепляется
  только за зацепки, других селекторов у него нет. Компилятор и линтер молчат. Краснеет:
  `test/app.test.tsx` — «рендерит форму и все зацепки».
- **Примитив привёз свой класс** (кит перестал быть безголовым) — оформление потребителя начнёт
  спорить с чужим, и разъедется оно у каждого по-своему. Краснеет: `test/app.test.tsx` — «не
  привозит ни одного класса от кита».
- **Части поля разъехались** (`Label` потерял связь с `Input`, описание не попало в
  `aria-describedby`) — визуально страница целая, доступность мертва. Краснеет:
  `test/app.test.tsx` — «подпись связана с вводом».
- **Составной `Select` перестал быть 1-to-1** (корень начал рисовать панель сам) — потребитель
  теряет возможность задать разметку панели. Краснеет: `test/app.test.tsx` — «панели до
  открытия нет, выбранный город доезжает до заявки».

### 4. Стили — `@web-core/style` и `@web-core/style-tools`

Поставок ДВЕ, и приложение объявляет обе: из набора значений берётся базовый слой
CSS, из ящика инструментов — механика сборки класса (`createStyle`, `cva`). Инструменты
необязательны: оформление вправе взять их у нас, у кого-то ещё или не брать вовсе.

**Из базового слоя берётся СБРОС, и только он** (ступень 2 роадмапа). Значения оформление
отсюда больше не берёт: скругления и длительности приходят скином (`src/skin.ts`), а лист их
ещё печатает — снимут его после нас, зоной `style`.

**Цвета у страницы нет ни одного, и это её рабочее состояние.** Цвет — решение
автора скина, а наш скин его не принимает: эталон проверяет шов, а не вкус. Голая по цвету и
одетая по форме — законное состояние, а не поломка.

- **Инструменты вернулись в набор значений** (реэкспорт «чтобы не ломать потребителей») —
  приложение соберётся как ни в чём не бывало, а необязательность станет ложью: инструменты
  снова привозит одна установка со значениями. Краснеет: `test/gate.test.ts` — «значения и
  инструменты — две разные поставки»: он сверяет манифест зоны и обе поверхности.
- **В поставку вернулась надеваемая палитра по умолчанию** — приложение БЕЗ скина снова
  приедет крашеным, соберётся зелёным и станет неотличимо от одетого; «нет скина — приложение
  голое» опять станет неправдой. Краснеет дважды: `test/gate.test.ts` — «набор значений — язык,
  а не палитра», и `test/chain.test.ts` — «вида в бандле нет».
- **Базовый слой не доехал до бандла** — страница поднимется без сброса, а выглядеть будет
  «почти так же»: браузерные умолчания похожи ровно настолько, чтобы пропажу не заметить.
  Краснеет: `test/chain.test.ts` — «в бандл попали оба слоя стилей». Носитель пробы —
  **маркер приезда базы**, и имя его приезжает импортом из зоны `style`, а не литералом:
  переименуют токен там — проба поедет следом, а не начнёт врать.
- **Кто-то назвал режим** (`color-scheme` в бандле, класс режима на корне) — голая страница
  перестала быть голой: без этой строки браузер отвечает `normal` и рисует светлое, с ней —
  показывает два разных вида по настройке человека, то есть выбирает вид. Называет
  свою половину только надетый скин, а его здесь нет. Краснеет: `test/chain.test.ts` — «вида в
  бандле нет».
- **`createStyle` перестал читать варианты внутри мемо** — класс застывает на значении момента
  вызова: кнопка навсегда остаётся в стартовом состоянии, хотя состояние приложения меняется.
  Краснеет: `test/app.test.tsx` — «на время ожидания кнопка занята, спиннер живой, класс
  пересчитан».
- **Приложение начало красить себя само** (класс режима или имя палитры на корне) — оно
  перестало быть голым, и половина скина снова приехала мимо скина. Краснеет:
  `test/app.test.tsx` — «режим документа не трогает НИКТО».

### 5. Скин — `@web-core/skin` плюс механика надевания из `runtime`

**Вид приходит скином, и другого пути к нему нет** (ступень 2 роадмапа). Запись скина лежит в
`src/skin.ts`, CSS из неё порождает механика скина в браузере, а кладёт его на документ
переключатель зоны `runtime` — та же дорога, которой скин доезжает до человека из хранилища.
Эталон обязан ходить дорогой потребителя: короткая дорога проверяла бы не то, что он увидит.

- **Оформление снова берёт значение из общего листа** (`var(--radius-md)` вместо имени скина) —
  собирается зелёным, выглядит так же, а человек, собравший вид в редакторе, увидит у себя
  другое: значение приехало мимо скина. Краснеет: `test/skin.test.ts` — «оформление не адресует
  ни одного имени из общего листа». Лист в пробе ПОРОЖДАЕТСЯ генератором зоны `style`, а не
  переписан перечнем: имена заводит она, и второй копии этого знания здесь нет.
- **Оформление адресует имя, которого не объявляет никто** (опечатка в `--app-round`) — из листа
  оно тоже не взято, поэтому первая проба зелёная, а вид пропал молча. Краснеет: та же проба,
  обратная сторона — «всё, что оформление адресует, объявляет скин».
- **Скругления выписали ступенями вместо семени** — кадр тот же, а пересеваемость исчезла:
  поменять вид одним значением больше нельзя. Краснеет: `test/skin.test.ts` — «скругления
  посеяны, а не выписаны ступенями».
- **Из скина ушёл рецепт** (остались одни переменные) — это уже не скин, а половина скина, ровно
  то, что фреймворк перестал возить. Краснеет: `test/skin.test.ts` — «скин одевает кнопку
  рецептом, а не переменными».
- **Вид кнопки вернулся в оформление** — два пути к одному результату, и побеждает всегда
  оформление: оно живёт вне слоёв и сильнее любого скинового правила, поэтому скин молча
  перестал бы значить что-либо. Краснеет: `test/chain.test.ts` — селектора кнопки в бандле быть
  не должно.

**Чего пробы зоны НЕ проверяют и почему.** Порождённый скином вид едет в каскадном слое, а слои
`jsdom` игнорирует целиком — вычисленное значение он вернёт таким же, как без скина. Поэтому
«снимут скин — страница потеряет вид» проверяется живым браузером (`tools/live-check/`), руками,
а след замера живёт в узле задачи. Последний замер: со скином кнопка `6px | 8px 14px | flex`,
без скина — `0px | 1px 6px | block`, кадры страницы до перехода и после совпали побайтово.

## Поломка шва, найденная этим гейтом и починенная (закрыта)

Оставлено как след: это ровно тот случай, ради которого приложение существует, — дефект жил в
поверхности пакета, все 43 теста зоны `style` были зелёными, и увидела его только сборка
потребителя.

**`tsc` не разрешал side-effect импорт `@web-core/style/css`** (`TS2882`):

```
src/main.tsx(9,8): error TS2882: Cannot find module or type declarations for
side-effect import of '@web-core/style/css'.
```

Механика: типы для CSS приезжают из `vite/client` строкой `declare module '*.css' {}`
(`node_modules/vite/client.d.ts:43`). Шаблон сопоставляется с ТЕКСТОМ спецификатора, поэтому
соседняя строка `@web-core/style/themes.css` проходила, а `/css` — нет: у него не
было расширения. Чинить у себя было нечем и не нужно: `tsconfig.json` содержит только
`extends`, а ambient-объявление в приложении спрятало бы поломку от всех, кто соберётся после
нас.

Починено в зоне `style`: подпуть назван с расширением, как соседний, —
`@web-core/style/base.css`, алиаса на старое имя нет. Правило `*.css` покрывает оба,
ambient-объявления не нужны никому. Строка здесь и в скелете поехала следом — как следствие,
а не вместо причины.

Соседа из этого разбора — `themes.css` — с тех пор **не существует**: палитра снята с поставки
целиком. Находка от этого не устарела: расширение в имени подпутя решает ту же
задачу и для `base.css`, оставшегося одним.

## Границы

Приложение не правит ни одну зону и ничего не публикует. Всё, что здесь выглядит неудобным в
поверхности пакетов, — находка про шов: она уходит комментом владельцу задетой зоны, а не
обходится на месте.
