# 🎨 skin — вид, который надевает демка

Здесь лежит **наряд целиком**: чем красить, какой формы вещи и что из этого надето вместе.
Приложение читает эти файлы и печатает из них CSS — по сети за видом оно не ходит.

```
skin/
  outfit.json     наряд: имя палитры + список имён форм
  palette.json    цвет и размеры: категории, ступени, светлая и тёмная половина
  forms/          по файлу на компонент — рецепт его вида
    button.json
    accordion.json
    …
```

## 🧩 Кто на что ссылается

`outfit.json` не содержит ни цвета, ни рецептов — только **имена**:

```json
{
  "name": "omnifield",
  "palette": "omnifield-palette",
  "forms": ["omnifield-button", "omnifield-accordion", "…"]
}
```

Имя палитры ищется в `palette.json`, имена форм — среди файлов `forms/`. Поэтому один и тот же
компонент одевается другим нарядом без единой правки кода: меняется набор файлов, а не исходники.

⚠️ **Имя внутри файла — главное, имя файла — для человека.** Файлы в `forms/` названы по
компоненту (`button.json`), чтобы их было легко найти глазами, а связь с нарядом держит поле
`name` внутри файла.

## ➕ Принести свою форму из редактора вида

Собрал в редакторе новый вид компонента или целую палитру — переноси сюда файлом, это штатный
путь, а не обходной.

1. **Забрать запись из службы хранения.** Содержимое записи (`state`) и есть содержимое файла —
   ничего конвертировать не нужно. Адрес службы свой у каждого; запрос — обычный GraphQL:

   ```sh
   curl -s "$PRESETS_URL/graphql" -H 'content-type: application/json' -d '{
     "query": "{ presets(kind: \"form\", name: [\"моя-кнопка\"]) { ... on Form { name component recipe keyframes variantTags } } }"
   }'
   ```

   Если редактор умеет отдать запись файлом — годится и он: формат тот же.

2. **Положить файл** в `forms/<компонент>.json`. Форма на компонент должна быть одна: две формы
   одного компонента в одном наряде — это отказ сборки, а не «победит последняя».

3. **Вписать её имя** в `outfit.json`, в список `forms`. Не вписал — файл просто не участвует.

4. **Перезапустить демку** и посмотреть. Наряд не собрался — механика скажет, чего не хватило
   (неизвестная палитра, ссылка на цвет, которого в палитре нет, два рецепта на один компонент).

## 🧠 Что важно знать

- **Палитра обязана закрывать пятёрку категорий** — `accent`, `neutral`, `danger`, `success`,
  `warning`. Сверх них можно объявлять свои сколько угодно.
- **Формы ссылаются на палитру по ролям, а не по цвету.** Поэтому смена палитры перекрашивает всё
  разом, и поэтому же рецепт, ссылающийся на несуществующую роль, не соберётся.
- **Светлая и тёмная половины — в одной палитре** (`light`/`dark`), и обе приезжают одним текстом
  CSS. Переключение половины ничего не догружает.
- **Компонент без формы — законное состояние.** Он нарисуется голым, а не сломается.
