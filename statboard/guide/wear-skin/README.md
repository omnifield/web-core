# 4. Одеть — откуда берётся вид

**Показываем:** тот же экран, что и раньше, но одетый. Вид приходит из наряда, а не из CSS-файла
рядом с компонентом.
**Зачем:** это главная развилка фреймворка. Компонент не носит своего вида — вид надевают на него.

## 🧩 Из чего собран вид

| Часть | Что это |
|---|---|
| **Палитра** | категории цвета (`accent`, `neutral`, `danger`, `success`, `warning` и свои), у каждой — лесенка ступеней |
| **Форма** | рецепт ОДНОГО компонента: что носит каждая его часть в каждом состоянии |
| **Наряд** | какую палитру и какие формы надеть вместе; у наряда есть имя |

Все три лежат в репозитории файлами — в папке [`skin/`](../../skin/README.md), рядом с этим
гайдом. По сети за видом приложение не ходит, и это важное свойство: демка одевается там, где
никакой службы вида нет вовсе.

```
skin/
  outfit.json     наряд: имя палитры + список имён форм
  palette.json    цвет и размеры, обе половины
  forms/          по файлу на компонент — весь кит одет
```

## 💻 Код

Источник вида — это **две функции**: как зовут наряды и какой у наряда CSS. Рядом с ними —
провайдер, который этот источник надевает; держим их одним файлом, потому что порознь они
бесполезны.

```tsx
// src/providers/skin.tsx
import { withPassports } from "@web-core/skin";
import type { Form, Outfit, Palette } from "@web-core/skin/model";
import { SkinProvider } from "@web-core/skin/solid";
import type { SkinSource } from "@web-core/skin/wear";
import type { ParentProps } from "@web-core/solid";
import { passportOf } from "@web-core/ui/passport";

import outfitJson from "../../skin/outfit.json";
import paletteJson from "../../skin/palette.json";

const outfit = outfitJson as unknown as Outfit;
const palette = paletteJson as unknown as Palette;

const forms = Object.values(
  import.meta.glob<Form>("../../skin/forms/*.json", { eager: true, import: "default" }),
);

const { assemble, generateSkinCss } = withPassports(passportOf);

const source: SkinSource = {
  names: () => [outfit.name],
  css: () => generateSkinCss(assemble(outfit, { palettes: [palette], forms }).skin),
};

export function Skin(props: ParentProps) {
  return (
    <SkinProvider source={source} options={{ fallback: { skin: outfit.name, mode: "light" } }}>
      {props.children}
    </SkinProvider>
  );
}
```

📂 **Формы забираются папкой, а не списком импортов.** `import.meta.glob` — штатная возможность
сборщика: положил файл в `forms/`, вписал его имя в наряд — он участвует, и ни одной строки в коде
править не нужно. Перечислять сорок форм по одной значит держать второй, ручной список того же
самого — он разойдётся с папкой на первой же новой форме.

🎯 **Имя наряда берётся из самого наряда** (`outfit.name`), а не пишется строкой в двух местах:
переименовали наряд в `outfit.json` — приложение не заметило.

Надевается он один раз, на корне:

```tsx
// src/app/index.tsx
import { Skin } from "../providers/skin";

export function App() {
  return (
    <Skin>
      <Screen />
    </Skin>
  );
}
```

⚠️ **Хук вида (`useSkin`, кейс 5) работает только ВНУТРИ `<Skin>`.** Позвать его в том же
компоненте, который `<Skin>` рисует, нельзя — контекст доступен потомкам, а не тому, кто их
создаёт. Отсюда и отдельный `<Screen />`: экран живёт под провайдером.

## 🧠 Что запомнить

- **Компонент просит свой CSS сам.** Каждый компонент кита при монтировании говорит механике скина,
  какой вид ему нужен, — страница ничего для этого не делает.
- **Без `SkinProvider` кит работает, просто голый.** Это законное состояние, а не ошибка:
  компонент обязан жить без вида вовсе.
- **Наряд собирается из имён.** В файле наряда лежат ИМЕНА палитры и форм, а сами записи — рядом,
  отдельными файлами. Поэтому один и тот же компонент одевается разными нарядами без правок кода.
- **`assemble` проверяет, а не просто склеивает.** Форма ссылается на цвет, которого нет в палитре,
  — наряд не соберётся и скажет, чего не хватило.

## 🚫 Чего тут нет

- Переключения светлой и тёмной половины — кейс 5.
- Второго варианта одного компонента — кейс 6.
- Рисования нового вида: здесь его только НАДЕВАЮТ. Собрал свою форму или палитру в редакторе —
  переносишь её сюда файлом, как описано в [`skin/README.md`](../../skin/README.md). Это штатный
  путь, а не обходной.
