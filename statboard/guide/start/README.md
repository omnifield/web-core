# 1. Старт — что уже собрано за тебя

**Показываем:** приложение поднимается одной командой, и всё, что нужно для работы, уже стоит.
**Зачем:** чтобы первый час не ушёл на конфиги. Их здесь трогать не нужно вообще.

## 🧱 Что стоит в репозитории и откуда

| Файл | Что делает | Откуда берётся |
|---|---|---|
| `vite.config.ts` | сборка и dev-сервер | фабрика конфига `@web-core/build` — одна строка, своей обвязки нет |
| `tsconfig.json` | типы | база `@web-core/build` |
| `vitest.config.ts` | тесты | пресет `@web-core/build` |
| `eslint.config.js` | канон Solid, выраженный машиной | пресет `@web-core/lint` |
| `nx.json` · `project.json` | цели (`lint`, `typecheck`, `test`, `build`) и паспорт проекта | свои, разбор — [`FLOW.md`](../../FLOW.md) |
| `src/index.tsx` | точка входа | `mountApp()` из `@web-core/solid/mount` |

```tsx
// src/index.tsx
import { mountApp } from "@web-core/solid/mount";

import { App } from "./app";

mountApp(App);
```

## 🧠 Что запомнить

- **`solid-js` напрямую не импортируется.** Везде `@web-core/solid` — тогда весь код ловит один и
  тот же реактивный движок, а не две его копии. Две копии ломают всё, что стоит на состоянии, и
  ломают молча.
- **Пакеты берутся номером версии** (`"@web-core/ui": "^0.4.0"`), и это сознательно: репозиторий
  одинаково работает и сам по себе (пакеты едут из реестра), и рядом с исходниками базы.
- **Конфиги не растут.** Понадобилось что-то от сборки — сначала смотри, умеет ли это
  `@web-core/build`; почти всегда умеет.
- **Инструменты зовутся через базу.** В скриптах стоят `web-core-vite` и `web-core-vitest` — это
  сборщик и тест-раннер, которые везёт `@web-core/build`. Своих копий рядом держать не нужно.
