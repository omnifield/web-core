# 6. Вариант — «такая же кнопка, но другая»

**Показываем:** один компонент, несколько видов — `data-variant`.
**Зачем:** чтобы не заводить `PrimaryButton`, `DangerButton` и ещё пять компонентов там, где
различается только вид.

## 💻 Код

```tsx
import { Button } from "@web-core/ui";

export function Variants() {
  return (
    <>
      <Button>Обычная</Button>
      <Button data-variant="primary">Главная</Button>
      <Button data-variant="danger">Опасная</Button>
    </>
  );
}
```

## 🧠 Что запомнить

- **Кит не знает списка вариантов.** `primary`, `danger`, `ghost` — не перечисление в коде
  компонента, а имена, объявленные в ФОРМЕ (та самая часть наряда из кейса 4). Хочешь новый
  вариант — дописываешь его в форму, компонент не трогаешь.
- **Имя, которого нет в форме, — не ошибка, а просто отсутствие правил.** Кнопка нарисуется
  обычной. Это нарочно: вид может приехать позже, и компонент не должен из-за этого падать.
- **Компонент допечатывает только тот вариант, который реально получил.** Форма с сотней вариантов
  не тащит их все в страницу.
- **Вариант меняет ВИД, а не устройство.** Если «вариант» меняет, из каких частей вещь состоит, —
  это уже другой случай, см. кейс 10.

## 🚫 Чего тут нет

- Настроек компонента (`orientation`, `multiple` и подобные): они тоже объявлены паспортом, но это
  поведение, а не вид, и выставляются обычным пропом.
