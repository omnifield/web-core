# 11. Накормить данными — `bind` и `repeat`

**Показываем:** сколько разделов будет у аккордеона, решают данные, а не код.
**Зачем:** это то, ради чего движок вообще нужен: структура растёт из данных.

## 💻 Код

```tsx
import { createSignal } from "@web-core/solid";
import { RenderTree } from "@web-core/assembly/render";
import { kitComponentRenderer } from "@web-core/ui/component-registry";

const { registry, instanceOf } = kitComponentRenderer();

export function Data() {
  const [items, setItems] = createSignal([
    { value: "what", label: "Что это" },
    { value: "how", label: "Как работает" },
  ]);

  const data = () => ({ items: items() });

  return (
    <>
      <button onClick={() => setItems([...items(), { value: "why", label: "Зачем" }])}>
        Добавить раздел
      </button>

      <RenderTree
        tree={instanceOf("accordion", {}, "base", data())}
        registry={registry}
        data={data()}
      />
    </>
  );
}
```

## 🧠 Что запомнить

- **`repeat` — «повтори эту ветку по каждому элементу».** В сборке аккордеона раздел объявлен ОДИН
  раз и повторяется по пути `/items`. Два элемента — два раздела, десять — десять.
- **`bind` — «возьми значение отсюда».** Подпись раздела не написана в дереве: она привязана к полю
  элемента. Поэтому одно и то же дерево показывает любые данные.
- **Форму данных объявляет сам компонент.** У аккордеона это список `{ value, label }`, у графика —
  строки плюс серии. Гадать не нужно: контракт объявлен компонентом и проверяется.
- **Данные идут в ДВА места.** В `instanceOf` — чтобы вырастить нужное число узлов, и в `RenderTree`
  — чтобы узлы прочитали свои значения. Это не дублирование: первое решает, сколько узлов, второе —
  что в них.
