# 9. Отрисовка движком — реестр, экземпляр, рендер

**Показываем:** три шага, которыми компонент рисуется движком вместо прямого JSX.
**Зачем:** это базовый поток для всего, что дальше — вид компонента, данные, события.

## 💻 Код

```tsx
import { RenderTree } from "@web-core/assembly/render";
import { kitComponentRenderer } from "@web-core/ui/component-registry";

// Шаг 1. Реестр — один раз на приложение, не на компонент и не на рендер.
const { registry, instanceOf } = kitComponentRenderer();

export function Rendered() {
  // Шаг 2. Экземпляр — готовая сборка компонента, а не сочинённое дерево.
  const tree = instanceOf("accordion", {});

  // Шаг 3. Отрисовка.
  return <RenderTree tree={tree} registry={registry} />;
}
```

## 🧠 Что запомнить

- **Реестр — один на приложение.** Он собирается из паспортов кита и знает, какой адрес каким
  компонентом рисовать. Заводить его на каждый экран не нужно.
- **`instanceOf` берёт ГОТОВУЮ сборку компонента.** Сборки — собственность самого компонента,
  доказанная его тестами. Приложение выбирает готовую по имени, а не пишет дерево литералом:
  сочинённое на лету дерево не проверено ничем и разъедется с компонентом на первом же его выпуске.
- **Второй аргумент — пропсы корня.** Туда кладут то, что обычно пишут прямо на компоненте
  (`data-variant`, настройки). В дерево это не влезает и его не меняет.
- **Ни одна из готовых сборок не подошла?** Это не повод писать дерево вручную — это повод
  попросить владельца компонента завести новую именованную сборку рядом с существующими.
