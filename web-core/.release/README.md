<h2 id="главное">🏠 Главное</h2>

🔍 Проверяет **опубликованные** пакеты со стороны потребителя: ставит их из реестра в пустой
проект во временной папке, импортирует каждый подпуть из `exports` и проверяет типы.

Зачем это отдельным шагом. Внутри репозитория пакеты соединены ссылками на соседние папки, и
поверхность поставки не участвует в работе вообще: `exports`, список файлов в тарболе, условия
резолва, диапазоны зависимостей. Ошибка в них невидима изнутри — сборка и тесты зелёные, а у
того, кто поставил пакет из реестра, ничего не работает. Установка со стороны — единственный
способ это увидеть.

<h2 id="команда">🚀 Команда</h2>

```bash
pnpm --filter @web-core/release release verify [--json]
```

| Ключ | Что делает |
|---|---|
| `--only <пакет>` | проверить один пакет вместо всей группы |
| `--no-types` | пропустить проверку типов — быстрее |
| `--registry <url>` | откуда ставить; по умолчанию берётся из окружения |

Коды возврата: `0` — принято или проверять нечего, `1` — отказ, `2` — команду позвали неверно.

<h2 id="отчёт">📋 Что в отчёте</h2>

`--json` отдаёт один конверт: `outcome` (`done` / `nothing` / `failed`), `summary` для человека и
`details` с разбором по каждому пакету — какие шаги прошли, сколько заняли и что ответили.
Временный проект каждой пробы остаётся на диске, путь указан в отчёте: там всё воспроизводится
руками.

⚠️ **Не всякий отказ означает сломанный пакет.** Проба импортирует пакеты голым Node, и часть
поставки так не импортируется по своей природе:

- **браузерный пакет** обращается к DOM — вне браузера он падает, и это нормально;
- **подпуть, отдающий не модуль** (файл стилей, конфиг) — импортировать его как модуль нельзя;
- **опциональная зависимость** требует, чтобы её поставил потребитель; проба этого не делает.

Признак настоящего дефекта — отказ, который повторяется в обычном потребительском сценарии:
сборка бандлером, установка с нужными зависимостями. Исчез при этом — значит упёрлись в границу
пробы, а не в поставку.

<h2 id="переменные">🎚️ Переменные</h2>

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `NPM_CONFIG_REGISTRY` (или `--registry`) | откуда ставить пакеты при проверке | реестр из окружения |
| токен реестра | доступ, если пакеты приватные | строка в пользовательском `~/.npmrc` или шаг пайплайна |

⚠️ Токен не кладут в `.npmrc` репозитория даже через переменную: pnpm не разворачивает переменные
в учётных данных из файла проекта и отказывает предупреждением. Файл коммитится — секрет ушёл бы
вместе с ним.

<h2 id="устройство">🧩 Устройство</h2>

| Файл | Что держит |
|---|---|
| `src/index.ts` | объявление команды и запуск программы |
| `src/verify.ts` | сама проверка: проба по каждому публикуемому пакету |
| `src/workspace.ts` | какие пакеты воркспейса публикуются, а какие нет |
| `src/run.ts` | запуск внешней команды с захватом вывода |
| `src/root.ts` | поиск корня воркспейса |

<h2 id="нет">🚪 Чего здесь нет</h2>

- **Версий, CHANGELOG и публикации** — это делает граф задач штатными средствами, настройка в
  `nx.json`, секция `release`. Порядок шагов — [`FLOW.md`](./FLOW.md).
- **Тегов, релизов и слияний** — они на стороне репозитория и его пайплайна.
- **Адреса реестра** — приходит переменной, в коде его нет.
