# generators

Код-генерация этого кита — один конфиг-файл на вид генерации, каждый производит своё из одних и
тех же папок компонентов (`src/*`).

Сам механизм — не отсюда, он в `@web-core/generators` (отдельный продукт репозитория,
`web-core/generators`, `GEN-9`): раннер вида `vite`/`webpack` (`@web-core/generators/engine` —
сам владеет обходом/чтением/записью/слиянием ручных зон) и CLI, который его запускает
(`cli.ts` — грузит конфиг ИСПОЛНЕНИЕМ, как всё остальное в этом инструменте, не разбором текста).
Здесь — только то, что знает про раскладку ИМЕННО этого кита: где у компонента паспорт, что значит
"часть", какой текст должен получиться. Ни одного `node:fs`/`node:path` для чтения дерева
компонентов — только `EntryContext` (`entry.has`/`entry.read`/`entry.resolve`/`entry.importModule`).

## Что здесь есть

| файл | что производит | команда |
|---|---|---|
| [`generate.config.ts`](generate.config.ts) | агрегирующие входы кита — один файл на ВСЕ компоненты сразу (`passport.ts`, `kit.ts`, `io.ts`, `index.ts`), четыре `AggregatePlugin` на одном скане | `pnpm run generate` |

Механическая документация (`README.md` на каждый компонент) и черновик-промпт для агента,
дописывающего прозу, — на очереди, следующей итерацией (`GEN-9`).

## Общее для всех конфигов здесь

**Компонент — это папка `src/*`, объявившая `entity/passport.ts`.** Ни один конфиг не ведёт
отдельный список компонентов руками — компонент, у которого нет `entity/passport.ts`, для любого
конфига этой папки просто не существует.

**Шаблоны — Handlebars-файлы (`*.hbs`), не TS-функции.** `templates/<вид>/*.hbs` — сам текст того,
что производится, живёт там, а не внутри логики сбора данных в конфиге.

**Каждый конфиг — свой Nx-таргет** (`package.json`, `nx.targets`), не часть сборки: порождённое
нужно раньше сборки, и гонять сборку ради генерации значило бы платить лишним проходом esbuild за
каждую мелочь.
