# ❓ FAQ

Короткие ответы на конкретные вопросы, которые уже возникали по этому компоненту. Не общая
документация (она в [`README.md`](./README.md)) и не план (он в [`ROADMAP.yaml`](./ROADMAP.yaml))
— только факты, каждый проверен на практике.

---

### Почему клик по чему-то совсем постороннему на странице иногда «проглатывался», а список селекта не закрывался?

**Коротко: список должен рендериться через портал в конец документа — без этого клики перехватывает не то.**

Плавающий список селекта рендерится не там, где стоит сам `<Select>` в дереве, а через портал прямо
в конец документа. Без портала более поздний, никак не связанный с селектом сосед где-то ещё на
реальной странице мог молча перехватывать клики, предназначенные списку. Это уже исправлено в
самом ките — упомянуто здесь как объяснение, почему именно так, если код придётся трогать.

### Почему `data-state="open"/"closed"` на списке ведёт себя иначе, чем `[hidden]` у аккордеона?

**Коротко: это реальное структурное отличие двух разных компонентов, не недосмотр в одном из них.**

У списка селекта метка состояния выставлена всегда, независимо от того, смонтирован ли узел сейчас
вообще. У раскрывающегося содержимого аккордеона — наоборот, скрытие идёт через нативный атрибут, а
не метку состояния. Не переносить привычку из одного компонента на другой не проверив — они устроены
по-разному специально, не по случайности.

### Почему индикатор выбранного пункта был неправильного цвета, хотя визуально казался нормальным?

**Коротко: свойство `color` бралось из ступени палитры без гарантии контраста — проверка это ловит.**

Ступени шкалы палитры делятся на те, что гарантируют контраст текста (можно красить `color`), и те,
что нет (только фон). Использовать вторые для текста — реальная, пойманная проверкой ошибка, даже
если на конкретной палитре разница на глаз незаметна. Проверять свойство `color` только ступенями,
специально предназначенными под текст.
