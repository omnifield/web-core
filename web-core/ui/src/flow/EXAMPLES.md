# 🧪 Примеры — как работать с `Flow`

Рабочий код для локального теста, не канон. Анатомия и рецепт — [`README.md`](./README.md). Здесь —
то, что можно скопировать и сразу погонять.

> [!IMPORTANT]
> **Вид приезжает атрибутом `data-variant` — у потока это ВСЯ раскладка целиком.** Ни направления,
> ни зазора, ни выравнивания в разметке нет и не будет: голый поток ничего не расставляет, и это
> его законное состояние. Имя вида придумывает не кит, а форма скина — запись в службе; `row`/
> `column` ниже это имена проверочного рецепта, в своей форме они могут быть другими (те же имена
> показывает витрина в карточке компонента).

> [!NOTE]
> У компонента нет своих `FAQ.md`/`ROADMAP.yaml` — разборы и план по нему живут в доке зоны
> (`web-core/ui/FAQ.md`, `web-core/ui/ROADMAP.yaml`).

## 1. Ручная сборка — ряд кнопок

Самый простой путь: JSX-композиция, без схемы и движка. Дети кладутся в поток напрямую — обёртка на
каждый чих не нужна.

```tsx
import { Button, Flow } from "@web-core/ui";

export function BasicFlowDemo() {
  return (
    <Flow data-variant="xxx">
      <Button data-variant="quiet">Отмена</Button>
      <Button data-variant="primary">Сохранить</Button>
    </Flow>
  );
}
```

Полезно проверить: без надетой формы кнопки встанут вплотную — зазор это ВИД, и его задаёт форма по
адресу `[data-scope="flow"]`, а не проп. Именно поэтому приложение, где отступы расставлены пропами,
скином потом не переодеть.

## 2. Когда нужен `item`

`item` заводится ради ОДНОГО элемента, у которого своё поведение в потоке: «это поле тянется, а
кнопка по содержимому». Свойства размещения живут на ребёнке, а дети потока — чужие компоненты, и
адресовать их правилом напрямую значило бы попасть во все сразу.

```tsx
import { Button, Field, FieldInput, Flow, FlowItem } from "@web-core/ui";

export function GrowingItemFlowDemo() {
  return (
    <Flow data-variant="xxx">
      <FlowItem>
        <Field data-variant="xxx">
          <FieldInput placeholder="Что ищем" />
        </Field>
      </FlowItem>

      <Button data-variant="primary">Найти</Button>
    </Flow>
  );
}
```

Полезно проверить: в форме скина правило пишется на `flow.item` — и попадает только на обёрнутый
элемент. Остальные дети остаются без обёртки и правила не получают: `item` необязателен именно
поэтому.

## 3. Направление — это вид

`row` и `column` в проверочном рецепте — не два разных компонента и не проп, а два имени вида:
поток одинаково выстроит ряд с переносом и колонку без него.

```tsx
import { Flow, FlowItem } from "@web-core/ui";

export function DirectionFlowDemo() {
  return (
    <>
      <Flow data-variant="row">
        <FlowItem>Первый</FlowItem>
        <FlowItem>Второй</FlowItem>
      </Flow>

      <Flow data-variant="column">
        <FlowItem>Пункт 1</FlowItem>
        <FlowItem>Пункт 2</FlowItem>
      </Flow>
    </>
  );
}
```

Полезно проверить: разница видна только с формой, где эти имена объявлены. Кит своего мнения о
направлении не имеет — взять ему его неоткуда, он безголовый.

## 4. Другой тег

`as` меняет корневой элемент — и у самого потока, и у отдельного `item`. Семантику выбирает тот,
кто ставит раскладку на страницу.

```tsx
import { Flow, FlowItem } from "@web-core/ui";

export function SemanticFlowDemo() {
  return (
    <Flow as="ul" data-variant="column">
      <FlowItem as="li">Первый пункт</FlowItem>
      <FlowItem as="li">Второй пункт</FlowItem>
    </Flow>
  );
}
```

Полезно проверить: в DOM настоящие `UL`/`LI`, адрес потока при этом на месте. Тот же предел, что у
кнопки и поверхности: `as` НА ДРУГОЙ компонент кита — не рабочий путь, побеждает адрес цели.

## 5. Рендер через движок — сборка `basic`

Та же композиция, но собранная по схеме и нарисованная `RenderTree`. Своего io у потока нет —
данных ему не нужно, в сборке лежат два элемента с текстом.

```tsx
import { RenderTree } from "@web-core/assembly/render";
import { kitComponentRenderer } from "@web-core/ui/component-registry";

const { registry, instanceOf } = kitComponentRenderer();

export function EngineFlowDemo() {
  return (
    <RenderTree
      tree={instanceOf("flow", { "data-variant": "xxx" }, "basic", {})}
      registry={registry}
      data={{}}
    />
  );
}
```

Полезно проверить: в сборке два элемента не случайно — предмет потока целиком в зазоре МЕЖДУ ними,
а между одним зазора нет и доказывать нечего. Состояний у потока нет ни одного: раскладка ничего не
хранит.

## Посмотреть живьём

Кит по умолчанию не несёт ни одного стиля, а у потока это доведено до предела: без формы скина он
не расставляет вообще ничего. Смотреть живьём — на dev-сервере приложения, где кит подключён вместе
со скином.

Граница та же, что у поверхности: раскладка — ВИД, а не поведение. Она меняет то, как компонент
выглядит, и не меняет того, что он показывает, — поэтому живёт в форме скина, а не в пропах кита.
