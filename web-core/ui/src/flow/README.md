<h2 id="анатомия">🧩 Анатомия</h2>

```
root
├─ item
└─ item …
```

| часть      | значение                                                                     | принимает внутри            | рисуется    |
| ---------- | --------------------------------------------------------------------------- | ------------------------------- | ------------- |
| ➡️ `root`  | поток — элементы идут друг за другом по одной оси; какой именно, говорит скин | `item`, текст, любой компонент | `Flow`      |
| 🔲 `item`  | место одного элемента в потоке — им адресуется «этот тянется, остальные по содержимому» | текст, любой компонент | `FlowItem`  |

Ни у `root`, ни у `item` своих состояний нет — раскладка ничего не хранит, только держит элементы и
адрес, к которому цепляется правило скина.

> [!NOTE]
> Ни направления, ни зазора, ни выравнивания в разметке. Всё это ВИД, и задаёт его скин по адресу
> (`data-scope="flow"`). Проп `gap` или `direction` означал бы, что кит знает, как выглядит
> раскладка, — а он безголовый и знать этого не может. Практическое следствие: приложение, где
> зазор проставлен пропами, скином не переодеть, и смена скина раскладку не поменяет. Голый поток
> поэтому ничего не расставляет — это законное рабочее состояние кита без скина.

> [!NOTE]
> `item` нужен, когда у одного элемента своё поведение в потоке («поле тянется, кнопка по
> содержимому») — свойства размещения (`flex`, `align-self`, `order`) живут на РЕБЁНКЕ, а дети
> потока — чужие компоненты; правило скина, адресующее их напрямую, попало бы на все сразу. `item`
> необязателен: элементы, которым размещение не нужно, кладут в поток напрямую, без обёртки на
> каждый чих.

Состояний нет ни у `root`, ни у `item`.

<h2 id="сборки">🏗️ Сборки</h2>

<h3 id="сборка-basic">🧱 basic</h3>

Ряд из двух элементов — предмет потока целиком в зазоре МЕЖДУ ними, а между одним зазора нет.

```
root
  item · text: "Первый"
  item · text: "Второй"
```

<h2 id="рецепт">🎨 Рецепт</h2>

Доказательный рецепт (`playground/recipe.ts`) — доказывает, что паспорт МОЖНО одеть целиком
настоящей скин-механикой (`skinGaps` пуст, CSS реально генерируется). В продакшене не участвует.

Две части, состояний нет — вместо них у потока две вариации: `row` (умолчание, ряд с переносом) и
`column` (список без переноса, каждый элемент своей строкой) — нужна списку в рельсах приложения,
направление это вид, потоку самому своего мнения о нём взять неоткуда.

> [!NOTE]
> Раскладка — вид, а не поведение: она меняет то, КАК компонент выглядит, и не меняет того, что он
> показывает. Поэтому она законна в скине, а не в пропах кита — та же граница, что уже проведена
> для поверхности (`surface/README.md`).

<h2 id="использование">🚀 Использование</h2>

**Ручная сборка** — компонент собирается вручную, JSX-композицией, без схемы и движка. Тег
выбирает потребитель через `as` — и у `Flow`, и у `FlowItem` по отдельности.

```tsx
<Flow data-variant="панель-действий">
  <Button>Отмена</Button>
  <Button data-variant="главная">Сохранить</Button>
</Flow>

<Flow data-variant="поиск">
  <FlowItem>
    <Input />
  </FlowItem>
  <Button>Найти</Button>
</Flow>
```

**Рендер через движок** — та же композиция, но по схеме (сборка `basic`), которую рисует
`RenderTree`.

```tsx
const tree = instanceOf("flow", {}, "basic", {});

<RenderTree tree={tree} registry={registry} data={{}} />;
```

**Список без переноса.** Вариант `column` — та же раскладка, без обёртки в дополнительный
компонент:

```tsx
<Flow data-variant="column">
  <FlowItem>Пункт 1</FlowItem>
  <FlowItem>Пункт 2</FlowItem>
</Flow>
```
