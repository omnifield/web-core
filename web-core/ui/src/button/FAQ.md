### Почему `<Button as={ДругойКомпонентКита}>` не всегда сохраняет вид и адрес кнопки?

**Коротко: работает только с голым тегом или с компонентом, который сам участвует в передаче адреса — иначе известный предел.**

Проверено эмпирически (`test/button.test.tsx`, `as={Toggle}`): финальный узел получает адрес ЦЕЛИ
(`data-scope="toggle"`), не кнопки (`data-scope="button"`) — весь скин кнопки перестаёт применяться
вовсе, узел красится как `toggle`.

Причина — механизм переговоров об адресе (`useAddress`/`isSlotAware` в `shared/utils/slot-chain.ts`)
рассчитан на композицию с ГОЛЫМ тегом (`as="a"` — работает, проверено) или с целью,
которая сама помечена как участвующая в этой передаче. `Toggle`, `ToggleGroupItem` и вообще любой
компонент кита, который безусловно ставит собственный адрес сам, не глядя, что просят снаружи, в
этой передаче не участвует — при композиции с ним всегда побеждает его собственный адрес.

Это касается не только кнопки — любая композиция «компонент кита `as=` другой компонент кита, не
участвующий в передаче адреса» ловит ту же потерю адреса. Решение сознательно не принято — это
межкомпонентный вопрос, не локальная правка одного компонента (задокументировано как известный
предел, 2026-09-04).

**Как составлять реально:** `as` на голый HTML-тег (`as="a"`, `as="div"`) — рабочий путь, адрес
кнопки сохраняется. Состояния `expanded`/`pressed` — не через `as`-композицию с другим
компонентом кита, а обычным атрибутом прямо на `<Button>` (`data-expanded=""`/`data-pressed=""`),
который владелец поведения ставит сам, без полиморфизма.

### Почему README когда-то упоминал сборки `icon`/`icon-text`, которых нет в коде?

**Коротко: остались от отменённой правки — код откатили, документацию тогда забыли.**

Кто-то по ошибке начал добавлять эти две сборки, был остановлен и откатил код, но `README.md` с их
описанием остался нетронутым до отдельного аудита. Урок не про кнопку конкретно — README и код
расходятся тихо, если поправить один и забыть другой. Проверять описание раздела по реальному
состоянию кода, не доверять тексту на слово.
