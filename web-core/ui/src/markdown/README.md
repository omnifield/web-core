# 📄 Markdown

<h2 id="главное">🏠 Главное</h2>

🏷️ other · 🧬 component · 📐 regular · 📦 `@web-core/ui`

Текст документа, нарисованный частями кита 📄 — каждый заголовок, абзац, список и блок кода получает
свой адрес и одевается скином вместе с остальными примитивами. Без этого документ рядом с одетым
китом читается как чужая страница: сменили наряд — компоненты переоделись, а текст вокруг остался
прежним.

Разбор разметки кит не пишет — берёт готовый (`solid-markdown` поверх unified/remark) и пользуется
его штатным входом: подменой узлов документа на свои компоненты. 🧩

<h2 id="анатомия">🧩 Анатомия</h2>

Восемь частей, и собирает их не схема, а сам текст: что нашлось в документе, то и нарисовано.

```
root
├─ heading
├─ paragraph
├─ list
├─ code
├─ table
├─ quote
└─ link
```

| часть | значение | принимает внутри | рисуется |
| --- | --- | --- | --- |
| 📄 `root` | документ целиком | ничего — части растит текст | `Markdown` |
| 🔠 `heading` | заголовок раздела; уровень несёт метка | ничего | `MarkdownHeading` |
| ¶ `paragraph` | абзац — основной объём документа | ничего | `MarkdownParagraph` |
| 📋 `list` | список пунктов, маркированный или нумерованный | ничего | `MarkdownList` |
| 💻 `code` | код блоком либо внутри строки | ничего | `MarkdownCode` |
| 🗂️ `table` | таблица документа | ничего | `MarkdownTable` |
| 💬 `quote` | цитата внутри документа | ничего | `MarkdownQuote` |
| 🔗 `link` | ссылка; адрес берётся из документа | ничего | `MarkdownLink` |

`accepts` у всех частей ПУСТОЙ, и это не забывчивость: место внутри каждой занято тем, что нашлось в
разметке источника, — положить туда узел через схему нечего.

Имена частей взяты из общего словаря кита (`shared/data/anatomy.ts`), а не придуманы здесь:
заголовок в документе — тот же заголовок, что у соседей по киту.

<h3 id="состояния">🎛️ Состояния</h3>

| часть | состояние | метка | откуда берётся |
| --- | --- | --- | --- |
| 🔠 `heading` | `level-1` … `level-6` | `data-level="1"` … `"6"` | уровень заголовка в документе |
| 📋 `list` | `ordered` | `data-ordered` | список нумерованный, а не маркированный |
| 💻 `code` | `inline` | `data-inline` | код стоит внутри строки текста |
| 🔗 `link` | `hover`, `focus-visible` | `:hover`, `:focus-visible` | работа браузера |

Уровень заголовка и нумерованность списка приносит сам разборщик документа — кит только
перекладывает их в метку, по которой рецепт различает вид. 🔁

Адресуется то, что перечислено выше, и ничего сверх: шапка, строки и ячейки таблицы, пункты списка,
`<pre>` вокруг блока кода и зачёркнутый текст своих частей не имеют, и правилом скина их вид сегодня
задать нечем.

<h2 id="использование">🚀 Использование</h2>

**Ручная сборка** — один компонент, текст приходит пропом `text`. Разметку внутри текста выбирает
источник, а не кит.

```tsx
<Markdown data-variant="xxx" text={"# Заголовок\n\nАбзац со `кодом`."} />
```

**Рендер через движок** — та же вещь по схеме (сборка `basic`), текст приезжает из данных.

```tsx
const data = { text: "# Заголовок\n\nАбзац." };
const tree = instanceOf("markdown", { "data-variant": "xxx" }, "basic", data);

<RenderTree tree={tree} registry={registry} data={data} />;
```

Имя вида (`xxx` выше) придумывает форма скина, а не кит: по нему компонент просит у скина свой CSS.

<h2 id="io">🔌 IO</h2>

Вход один — текст документа:

```ts
{ text: string }
```

Выхода у компонента нет: документ ничего не сообщает наружу, он его показывает.

<h2 id="сборки">🏗️ Сборки</h2>

<h3 id="сборка-basic">🧱 basic</h3>

Один узел: части растит сам текст, дерева схемы под них нет — как у таблицы и диаграммы.

```
root · bind text ← /text
```

<h2 id="рецепт">🎨 Рецепт</h2>

Доказательный рецепт (`playground/recipe.ts`) одевает все восемь частей и все девять состояний: шесть
ступеней заголовка, нумерованный список, код внутри строки, наведение и фокус на ссылке. Две вариации
— `article` (по умолчанию) и `compact`, где вертикальные интервалы и размер текста плотнее.

> [!IMPORTANT]
> Компонент показывает ЧУЖОЙ текст — произвольную разметку из источника, которым кит не управляет.
> Что с этим делает разборщик по умолчанию и что остаётся на потребителе — разобрано в
> [`FAQ.md`](../../FAQ.md) зоны; там же про вложенный узел разборщика внутри `root`.
