# 🗺️ Surface

<h2 id="главное">🏠 Главное</h2>

🏷️ layout · 🧬 component · 📐 regular · 📦 `@web-core/ui`

Плоскость 🗺️, отделяющая содержимое от того, что под ним — карточка, панель, полка. Сама по себе
ничего не решает и не хранит: какой у неё вид (обычный фон, приподнятая рамка и так далее), решает
только вид, который ей дали, — компонент лишь несёт адрес, за которым скин может закрепить правило.

<h2 id="анатомия">🧩 Анатомия</h2>

Один узел, без внутреннего деления — стилизуется целиком, а не по частям.

```
root
```

| часть     | значение                                                                           | принимает внутри       | рисуется  |
| --------- | ---------------------------------------------------------------------------------- | ---------------------- | --------- |
| 🗺️ `root` | плоскость — фон, рамка, тень и скругление отделяют содержимое от того, что под ним | текст, любой компонент | `Surface` |

Своих состояний нет — плоскость ничего не хранит, чем её вид мог бы отличаться сам по себе.
Наведение и фокус принадлежат тому, что лежит ВНУТРИ неё (кнопке, ссылке, полю), а не ей самой;
объяви кит их здесь, скин получил бы правило, которое никогда не сработает.

> [!NOTE]
> У кита это первый компонент вовсе без поведения. До него весь кит был интерактивным — кнопки,
> поля, меню, окна: плоскости (карточки, панели, полки) собирались в приложении своим `<div
class="…">`, и вид у них жил там же, вне доступа скина — адреса не было, не было и правила.
> `Surface` не несёт ни одного значения по умолчанию: ни фона, ни рамки, ни тени, ни скругления,
> ни отступа. Голая поверхность выглядит как ничто, и это её законное рабочее состояние — страница
> «Скин»: нет скина — приложение голое.

> [!NOTE]
> Вложенная плоскость — не часть, а отдельный компонент. Карточка внутри панели — это ДВА
> `Surface`, а не `root` с вложенным `root`: обе плоскости самостоятельны, обе одеваются своим
> собственным правилом, и вложенность у них ровно та, что в дереве JSX или сборки.

<h2 id="использование">🚀 Использование</h2>

Собрать плоскость можно вручную, по схеме, или вложенными друг в друга — карточка внутри панели. 🧩

**Ручная сборка** — компонент собирается вручную, JSX-композицией, без схемы и движка. Тег выбирает
потребитель через `as`: плоскость бывает `<section>`, `<article>`, `<aside>`, `<li>` — семантику
знает тот, кто ставит её на страницу; прибей кит `<div>` — навязал бы разметку, которую потом не
снять без мажора.

```tsx
<Surface data-variant="variantName">
  <Flow data-variant="variantName">…</Flow>
</Surface>

<Surface as="section" aria-labelledby="итоги">…</Surface>
```

**Рендер через движок** — та же композиция, но по схеме (сборка `basic`), которую рисует
`RenderTree`.

```tsx
const tree = instanceOf("surface", {}, "basic", {});

<RenderTree tree={tree} registry={registry} data={{}} />;
```

**Вложенность плоскостей.** Панель с приподнятой карточкой внутри — два независимых `Surface`,
каждый со своим вариантом (оба реальные, из `playground/recipe.ts`):

```tsx
<Surface data-variant="plain">
  <Surface data-variant="raised">…</Surface>
</Surface>
```

<h2 id="сборки">🏗️ Сборки</h2>

<h3 id="сборка-basic">🧱 basic</h3>

Поверхность с содержимым.

```
root · text: "Поверхность"
```

<h2 id="рецепт">🎨 Рецепт</h2>

Одна часть, состояний нет — вместо них у поверхности две вариации: `plain` (обычный фон) и `raised`
(тот же фон приглушённым, плюс тонкая рамка) — приподнятая плоскость отделяется от страницы именно
светлотой, а не тенью.

> [!NOTE]
> Здесь вариационная ось несёт ВЕСЬ вид компонента — «карточка», «панель», «утопленная» — это
> имена, которые человек даёт вариации в редакторе, а кит пропускает насквозь. Своих имён вариаций
> у кита нет и быть не может — иначе он объявил бы вид, которого не умеет проверить.
