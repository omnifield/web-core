# 🧪 Примеры — как работать с `Surface`

Рабочий код для локального теста, не канон. Анатомия и решения — [`README.md`](./README.md) /
[`FAQ.md`](./FAQ.md), план — [`ROADMAP.yaml`](./ROADMAP.yaml). Здесь — то, что можно скопировать и
сразу погонять.

> [!IMPORTANT]
> **Вид приезжает атрибутом `data-variant` — у плоскости это ВЕСЬ компонент целиком.** Своего вида
> она не несёт ни капли: ни фона, ни рамки, ни тени, ни скругления, ни отступа. Без назначенного
> вида плоскость выглядит как ничто — это её законное рабочее состояние, а не поломка. Имя вида
> придумывает не кит, а форма скина — запись в службе; в примерах ниже стоит `data-variant="xxx"`,
> подставьте имя своей формы (`plain`/`raised` — имена проверочного рецепта кита, те же имена
> показывает витрина в карточке компонента).

## 1. Ручная сборка — карточка с содержимым

Самый простой путь: JSX-композиция, без схемы и движка. Плоскость — один узел: внутрь кладётся что
угодно, стилизуется она целиком, по частям делить нечего.

```tsx
import { Surface } from "@web-core/ui";

export function BasicSurfaceDemo() {
  return (
    <Surface data-variant="xxx">
      <h3>Итоги месяца</h3>
      <p>Выручка выросла на 12%.</p>
    </Surface>
  );
}
```

Полезно проверить: на узле стоит `[data-scope="surface"][data-part="root"]` и ваш `data-variant` —
это всё, что плоскость делает. Уберите вид — узел останется, но выглядеть будет никак: правило
скина крепится именно к имени вида.

## 2. Тег выбирает потребитель

`as` меняет корневой элемент: плоскость бывает `<section>`, `<article>`, `<aside>`, `<li>` —
семантику знает тот, кто ставит её на страницу, поэтому кит `<div>` не прибивает.

```tsx
import { Surface } from "@web-core/ui";

export function SemanticSurfaceDemo() {
  return (
    <Surface as="section" data-variant="xxx" aria-labelledby="totals-title">
      <h2 id="totals-title">Итоги</h2>
      <p>…</p>
    </Surface>
  );
}
```

Полезно проверить: в DOM настоящий `SECTION`, а адрес и вид остались плоскостиными. Предел тот же,
что у кнопки: `as` НА ДРУГОЙ компонент кита — не рабочий путь, побеждает адрес цели, и правило
плоскости перестаёт применяться (проверено на паре `Flow`/`Surface`, обе свои — дело не в чужой
библиотеке под капотом, а в самой механике передачи адреса).

## 3. Плоскость внутри плоскости

Карточка внутри панели — это ДВА независимых `Surface`, каждый со своим видом, а не корень с
вложенным корнем: у плоскости одна часть, вложенность у неё ровно такая, как в разметке.

```tsx
import { Surface } from "@web-core/ui";

export function NestedSurfaceDemo() {
  return (
    <Surface data-variant="plain">
      <h3>Панель</h3>

      <Surface data-variant="raised">
        <p>Приподнятая карточка внутри панели</p>
      </Surface>
    </Surface>
  );
}
```

Полезно проверить: в разметке два узла `[data-part="root"]` с разными `data-variant` — каждый
одевается своим правилом независимо. В проверочном рецепте приподнятость сделана светлотой и тонкой
рамкой, а не тенью; в своей форме это ваше решение.

## 4. Рендер через движок — сборка `basic`

Та же плоскость, но собранная по схеме и нарисованная `RenderTree`. Своего io у компонента нет
вовсе — данных ему не нужно, в сборке лежит только текст-заглушка.

```tsx
import { RenderTree } from "@web-core/assembly/render";
import { kitComponentRenderer } from "@web-core/ui/component-registry";

const { registry, instanceOf } = kitComponentRenderer();

export function EngineSurfaceDemo() {
  return (
    <RenderTree
      tree={instanceOf("surface", { "data-variant": "xxx" }, "basic", {})}
      registry={registry}
      data={{}}
    />
  );
}
```

Полезно проверить: вид едет вторым аргументом `instanceOf` — это пропы КОРНЯ, туда же уходит `as`,
если нужен другой тег. Состояний у плоскости нет ни одного: наведение и фокус принадлежат тому, что
лежит ВНУТРИ неё, — объяви кит их здесь, скин получил бы правило, которое никогда не сработает.

## Посмотреть живьём

Кит по умолчанию не несёт ни одного стиля, а у плоскости это доведено до предела: без формы скина
она невидима. Смотреть живьём — на dev-сервере приложения, где кит подключён вместе со скином.

Проверочный рецепт из `playground/recipe.ts` — доказательство, что паспорт одевается целиком, а не
поставка: `plain`/`raised` там ради доказательства, а не как обязательный словарь имён. Полный
рабочий прогон — `test/surface.test.tsx`.
