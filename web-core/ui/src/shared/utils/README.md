# 🧵 Utils

Инструменты — функции, которые компонент зовёт, а не данные, которые он подставляет.

- **`address.ts`** — имена двух адресных атрибутов (`data-scope`/`data-part`), написанные ОДИН
  раз на весь кит. Название пары приходит от построителя анатомии, а не придумано здесь; но
  прочитать её приходится раньше, чем становится известен паспорт конкретного компонента (именно
  по ней компонент и опознаётся). Написать эту пару трижды — в ките, в читателе паспорта, в
  форме — значило бы однажды дать им разъехаться молча.
- **`slot-chain.ts`** — снятие ЧУЖОГО адреса с пропов (`dropAddress`) и подготовка СВОЕГО
  (`useAddress`), плюс отдельная цепочка именных зацепок для композиции через `as={...}`
  (`useSlot`/`slotAware`). Правило одно и то же в обоих случаях: адрес и зацепки ставит тот, кто
  реально рисует узел, и ставятся они ПОСЛЕДНИМИ — так, что явно переданный пропом чужой адрес не
  может случайно подменить настоящий, от кого бы он ни пришёл — от потребителя, написавшего его
  руками, или от чужого внешнего звена, спредящего свои пропы на вставленный компонент.

  Адрес и зацепка ведут себя ПО-РАЗНОМУ, и это не случайность: адрес принадлежит внутреннему
  компоненту (тому, чем вещь ЯВЛЯЕТСЯ визуально) и никуда не едет, а имена зацепок едут ВНИЗ по
  композиции и накапливаются списком (`data-slot~="button"`, а не последнее переписывает
  предыдущее). Проп для зацепки выбран не случайно: контекст утёк бы не только в компонент из
  `as`, но и в ДЕТЕЙ композиции; символьный ключ не пережил бы цепочку `splitProps`/`mergeProps`;
  обычный строковый проп «в лоб» просочился бы в разметку атрибутом, если `as` — просто имя тега.
  Поэтому прокидывается только тем, кто явно помечен как умеющий его снять (`slotAware`) — всем
  остальным (тегам, чужим компонентам) не передаётся ничего.
- **`trace.ts`** — необязательные perf-трейсы жизни примитива (`traceLife`), включаются только
  явным глобальным флагом. Выключенный трейс не аллоцирует и не подписывается ни на что — первая
  же строка выходит из функции до какой-либо работы, поэтому цена включения по умолчанию — ровно
  ноль.
- **`collection.ts`** — единая точка входа для механизма коллекции, общего для любого компонента,
  построенного на выбираемом перечне пунктов. Раньше каждый такой компонент вёз СВОЮ копию того же
  реэкспорта из СВОЕГО входа поставщика — работало, но задваивало одно и то же имя в разных
  модулях; следующий компонент с той же нуждой подключает готовое, а не заводит третью копию.
- **`skin-life.ts`** — `useKitLife(passport, props)`, зовётся первой строкой почти каждого
  `root.tsx`: трейс (`ui.${passport.component}` — метка берётся из самого паспорта, не
  набирается второй раз руками), `useComponentSkin` из `@web-core/skin/solid` и
  `useComponentValidation` из `@web-core/form/solid` одним вызовом — возвращает результат
  последнего (`Accessor<ComponentValidation | undefined>`), первые два молчаливые. Замена трёх
  ручных строк на файл одной; разбор — `README.md`, раздел «Скин».
