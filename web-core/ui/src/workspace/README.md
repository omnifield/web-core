<h2 id="анатомия">🧩 Анатомия</h2>

```
root
├─ header 🔝
├─ sidebar ◀️
├─ main 🖥️
├─ rightbar ▶️
└─ footer 🔻
```

| часть        | значение                                                           | принимает внутри | рисуется              |
| ------------ | --------------------------------------------------------------------- | ------------------ | ----------------------- |
| 🖥️ `root`    | каркас приложения целиком — держит все именованные слоты в одной сетке | все пять слотов     | `Workspace`             |
| 🔝 `header`  | верхняя полоса — не на всю высоту, только над показом и правой панелью | текст, любой компонент | `WorkspaceHeader`   |
| ◀️ `sidebar` | левая колонка — во всю высоту, рядом и с шапкой, и с показом           | текст, любой компонент | `WorkspaceSidebar`  |
| 🖥️ `main`    | показ — единственный слот, который есть всегда                        | текст, любой компонент | `WorkspaceMain`     |
| ▶️ `rightbar`| правая колонка — необязательна; не положена в сборку, колонка схлопывается сама | текст, любой компонент | `WorkspaceRightbar` |
| 🔻 `footer`  | нижняя полоса — необязательна; не положена в сборку, строка схлопывается сама | текст, любой компонент | `WorkspaceFooter`   |

Своих состояний ни у одной части нет — раскладка ничего не хранит, только держит слоты.

> [!NOTE]
> Не вариация сетки (`grid`). У сетки один вид части — `cell`, и ячейки неотличимы адресом:
> правило скина, написанное на `grid.cell`, попадает на все ячейки разом. Каркас приложения —
> четыре разные роли (шапка, рельсы, показ, боковая панель), каждая со своим видом (у рельсов своя
> подложка, у шапки своя высота), и им нужны разные адреса — отсюда пять именованных частей вместо
> одной, различаемой порядком детей.

<h2 id="настройки">🎚️ Настройки</h2>

| настройка   | значения | по умолчанию | означает                                                                                    |
| ----------- | -------- | ------------- | ------------------------------------------------------------------------------------------------ |
| `outlined`  | вкл/выкл | выкл          | тонкий шов между занятыми слотами плюс свой фон у каждого — когда блоки одного цвета и без него сливаются друг с другом |

> [!NOTE]
> Не бордер на каждом слоте. Пять независимых рамок на соседних узлах на стыке дают двойную линию
> (по 1px с каждой стороны), а в точке, где сходится три-четыре слота, — нахлёст нескольких
> отрезков вместо прямого угла. Взамен — `gap` на `root` (шов — это закраска корня, проступающая
> сквозь зазор сетки, везде одной толщины) плюс свой фон у каждого занятого слота поверх шва.

<h2 id="сборки">🏗️ Сборки</h2>

Восемь именованных раскладок — настоящие, узнаваемые схемы рынка, не собственная выдумка кита:

| сборка            | слоты                                | источник имени                                                          |
| ------------------ | -------------------------------------- | --------------------------------------------------------------------------- |
| `stacked`          | header, main                           | Tailwind UI, «Stacked layouts»                                              |
| `sidebar`          | sidebar, main                          | Tailwind UI, «Sidebar layouts»                                              |
| `sidebar-header`   | sidebar, header, main                  | тот же «sidebar» плюс верхняя полоса                                        |
| `right-rail`       | main, rightbar                         | «right rail» блога/документации                                            |
| `multi-column`     | sidebar, main, rightbar                | Tailwind UI, «Multi-column layouts» — почта, доска задач                    |
| `dashboard`        | header, sidebar, main, rightbar        | общепринятое название для этой комбинации слотов                            |
| `sidebar-footer`   | header, sidebar, main, footer          | «sidebar»/«sidebar-header» плюс подвал                                      |
| `holy-grail`       | все шесть                              | классический «Holy Grail Layout» — header+footer+три колонки               |

<h2 id="рецепт">🎨 Рецепт</h2>

Доказательный рецепт (`playground/recipe.ts`) — доказывает, что паспорт МОЖНО одеть целиком
настоящей скин-механикой (`skinGaps` пуст, CSS реально генерируется). Настоящий рецепт продукта
живёт формой `omnifield-workspace` в службе пресетов, не здесь.

Три варианта раскладки — одна и та же сетка строк/колонок, различается только тем, какой слот
какую именованную область занимает (`gridTemplateAreas`):

- **`sidebar-first`** (по умолчанию) — рельсы и правая панель тянутся через ВСЮ высоту, мимо шапки
  и подвала; шапка и подвал стоят между ними. То же самое различие делает `AppShell` Mantine своим
  `layout="alt"`.
- **`header-first`** — шапка и подвал во всю ширину строкой сверху и снизу, боковые колонки только
  в средней строке между ними. Классический «Holy Grail Layout».
- **`header-full`** — гибрид: шапка во всю ширину, как у `header-first`, но подвал — не на всю
  ширину, а только под показом, между рельсами и правой панелью (которые ради этого тянутся мимо
  него, как у `sidebar-first`, но не мимо шапки).

<h2 id="использование">🚀 Использование</h2>

**Ручная сборка** — компонент собирается вручную, JSX-композицией, без схемы и движка. Слоты кладут
в любом порядке — куда встанет каждый, решает скин через `grid-template-areas`, не порядок в
разметке.

```tsx
<Workspace>
  <WorkspaceSidebar>…</WorkspaceSidebar>
  <WorkspaceHeader>…</WorkspaceHeader>
  <WorkspaceMain>…</WorkspaceMain>
  <WorkspaceRightbar>…</WorkspaceRightbar>
</Workspace>
```

**Необязательные слоты по-настоящему необязательны.** Не смонтирован узел `WorkspaceRightbar` —
колонка под него схлопывается сама средствами CSS, а не условием в разметке потребителя.

```tsx
<Workspace>
  <WorkspaceHeader>…</WorkspaceHeader>
  <WorkspaceMain>…</WorkspaceMain>
</Workspace>
```

**Рендер через движок** — та же композиция, но по схеме (например, сборка `holy-grail`), которую
рисует `RenderTree`.

```tsx
const tree = instanceOf("workspace", {}, "holy-grail", {});

<RenderTree tree={tree} registry={registry} data={{}} />;
```

**Шов между слотами.**

```tsx
<Workspace outlined>
  <WorkspaceHeader>…</WorkspaceHeader>
  <WorkspaceMain>…</WorkspaceMain>
</Workspace>
```
