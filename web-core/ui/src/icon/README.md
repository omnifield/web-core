# 🔣 Icon

<h2 id="главное">🏠 Главное</h2>

🏷️ other · 🧬 component · 📐 compact · 📦 `@web-core/ui`

Одна иконка 🔣 — какая картинка встанет за именем `name`, знает только сам компонент; чем именно
она нарисована, потребителю не видно и не важно. Имена — не сквозной проброс чужой библиотеки, а
СВОЙ словарь кита (`entity/catalog.ts`): нужного имени нет — добавляется строкой туда, и это не
обход механизма, а сам механизм. Почему словарь, а не «любое имя lucide» — в
[`FAQ.md`](./FAQ.md).

<h2 id="анатомия">🧩 Анатомия</h2>

Один узел, без внутреннего деления — вся иконка целиком.

```
root
```

| часть      | значение                                                            | принимает внутри | рисуется |
| ---------- | -------------------------------------------------------------------- | ------------------ | -------- |
| 🔣 `root` | сама иконка — какой именно вид у неё, решает `name`, размер и цвет — рецепт | ничего              | `Icon`   |

Своих состояний нет — иконка ничего не хранит, чем её вид мог бы отличаться сам по себе.

<h2 id="использование">🚀 Использование</h2>

Собрать иконку можно вручную или по схеме через движок. 🧩

**Ручная сборка** — компонент собирается вручную, JSX-композицией, без схемы и движка.

```tsx
<Icon name="chevron-down" />
```

**Рендер через движок** — та же композиция, но по схеме (сборка `basic`), которую рисует
`RenderTree`.

```tsx
const tree = instanceOf("icon", {}, "basic", {});

<RenderTree tree={tree} registry={registry} data={{}} />;
```

> [!NOTE]
> Иконка резолвится асинхронно — `createResource` дожидается динамического импорта, прежде чем
> показать хоть что-то. На первом кадре рендера в разметке ничего нет, `<svg>` появляется тем же
> тиком, что и разрешённый импорт, не раньше. Проверено эмпирически: фиксированная пауза в один тик
> (`setTimeout(resolve, 0)`) оказалась короче реального времени импорта под Vite/Vitest — тест
> дожидается результата поллингом (`vi.waitFor`), а не угаданным числом миллисекунд.

<h2 id="io">🔌 IO</h2>

Иконке достаточно одного имени из словаря кита, чтобы решить, какую картинку показать. Сама она ничего никуда не
сообщает — только рисует то, что попросили, никаких кликов и событий у неё нет.

<h3 id="io-вход">📥 Вход</h3>

```json
{
  "name": "string"
}
```

<h3 id="io-выход">📤 Выход</h3>

Ничего — иконка не интерактивный виджет, событий она не поднимает.

<h2 id="сборки">🏗️ Сборки</h2>

Одна сборка, потому что показывать тут особо нечего разными способами — иконка и есть картинка по
имени, больше ничего.

<h3 id="сборка-basic">🧱 basic</h3>

Одна иконка по фиксированному имени.

```
root · name: "check"
```

<h2 id="рецепт">🎨 Рецепт</h2>

Одна часть, состояний нет. Базовый вид — размер шрифта (`1em` на обе стороны) и цвет текста
(`currentColor`): иконка растёт и красится вместе с окружающим текстом, если её явно не
переопределить.

> [!NOTE]
> Как и у `Surface`, вариационная ось (`data-variant`) здесь — открытое имя: кит не хранит списка
> своих вариаций, имя даёт человек в редакторе, кит пропускает его насквозь.

<h2 id="доступность">♿ Доступность</h2>

По умолчанию иконка декоративна — библиотека, которая рисует конкретную картинку, сама ставит
`aria-hidden="true"` на получившийся `<svg>` (проверено эмпирически на реальном рендере). Если
иконка — единственный носитель смысла (кнопка совсем без текста, только с иконкой внутри), подпись
даёт не сама иконка, а то, что её несёт: `aria-label` на кнопке или ссылке снаружи, не на `Icon`.
