# 🧪 Примеры — как работать с `Icon`

Рабочий код для локального теста, не канон. Анатомия и решения — [`README.md`](./README.md) /
[`FAQ.md`](./FAQ.md), план — [`ROADMAP.yaml`](./ROADMAP.yaml). Здесь — то, что можно скопировать и
сразу погонять.

> [!IMPORTANT]
> **У иконки вида нет — и это единственное исключение в ките.** Обычно стилизация приезжает
> атрибутом `data-variant` на корне компонента, но `IconProps` объявляет РОВНО один проп (`name`), а
> сам компонент печатает на `<svg>` только адрес части (`data-scope`/`data-part`) — ни один
> консьюмерский атрибут до разметки не доходит. Значит `data-variant` иконке передать нечем:
> размер и цвет она берёт от окружения (`1em`/`currentColor` в проверочном рецепте) либо от правил
> формы скина, написанных на её адрес. Ось вида в паспорте при этом объявлена — см. «Посмотреть
> живьём».

## 1. Ручная сборка — одна иконка

Самый простой путь: JSX без схемы и движка. `name` берётся из СЛОВАРЯ кита
(`entity/catalog.ts`) — это не сквозной проброс имён чужой библиотеки: нужного имени нет, значит
его добавляют строкой в словарь, и это сам механизм, а не обход.

```tsx
import { Icon } from "@web-core/ui";

export function BasicIconDemo() {
  return <Icon name="chevron-down" />;
}
```

Полезно проверить: в разметке настоящий `svg[data-scope="icon"][data-part="root"]` — но НЕ на
первом кадре: имя резолвится динамическим импортом, и до его разрешения компонент честно не рисует
ничего (ни заглушки, ни пустого места). В тесте это ждут поллингом (`vi.waitFor`), а не
фиксированной паузой.

## 2. Иконка внутри текста — размер и цвет берутся от окружения

Базовый вид проверочного рецепта — `1em` на обе стороны и `currentColor`: иконка растёт и красится
вместе с соседним текстом, пока форма скина не скажет иначе.

```tsx
import { Icon } from "@web-core/ui";

export function InlineIconDemo() {
  return (
    <p style={{ "font-size": "1.5rem", color: "crimson" }}>
      <Icon name="triangle-alert" /> Внимание: размер и цвет унаследованы
    </p>
  );
}
```

Полезно проверить: смените `font-size`/`color` у родителя — иконка меняется вместе с текстом, не
требуя собственных пропов. Своих состояний у неё нет вовсе: иконке нечем отличаться самой от себя.

## 3. Иконка как единственный смысл — подпись даёт носитель

По умолчанию иконка декоративна: библиотека сама ставит `aria-hidden="true"` на получившийся
`<svg>`. Если кнопка состоит из одной иконки, доступное имя даёт КНОПКА, а не иконка.

```tsx
import { Button, Icon } from "@web-core/ui";

export function IconOnlyButtonDemo() {
  return (
    <Button aria-label="Удалить строку" onClick={() => console.log("удалил")}>
      <Icon name="trash" />
    </Button>
  );
}
```

Полезно проверить: у `<svg>` стоит `aria-hidden="true"`, а доступное имя читается с кнопки. Ставить
`aria-label` на саму `Icon` не нужно — он окажется на скрытом от дерева доступности узле.

## 4. Нужного имени в словаре нет

Словарь кита закрыт по типу: `name` — union реальных имён, а не `string`. Опечатка в JSX ловится
типами сразу; а вот имя, пришедшее ДАННЫМИ (io-схема держит `z.string()`), типом не проверяется — и
несуществующее уходит необработанным отказом промиса, без заглушки и без видимой ошибки.

```tsx
import { Icon } from "@web-core/ui";

export function MissingIconDemo() {
  // ❌ так не соберётся — имени нет в словаре, это ошибка типов
  // return <Icon name="rocket" />;

  // ✅ пока имя не заведено — берём то, что в словаре есть
  return <Icon name="circle-question-mark" />;
}
```

Полезно проверить: имя добавляется одной строкой в `entity/catalog.ts` — словарь растёт заявкой.
Имя в словаре ничего не весит, пока его не отрисуют: значение — ленивый `import()`, в бандл
потребителя едет только реально названная иконка.

## 5. Рендер через движок — сборка `basic`

Та же иконка, но собранная по схеме и нарисованная `RenderTree`. В сборке имя зашито (`"check"`);
если имя должно приезжать данными, узел в своей сборке связывают через `bind`.

```tsx
import { RenderTree } from "@web-core/assembly/render";
import { kitComponentRenderer } from "@web-core/ui/component-registry";

const { registry, instanceOf } = kitComponentRenderer();

export function EngineIconDemo() {
  return (
    <RenderTree
      tree={instanceOf("icon", {}, "basic", {})}
      registry={registry}
      data={{}}
    />
  );
}
```

Полезно проверить: иконка появляется на кадр позже остального дерева. И важное для СОСЕДЕЙ по
сборке: `RenderTree` заворачивает ВСЁ дерево в один общий `<Suspense>` — пока иконка где-то внутри
не разрешилась, пусто всё дерево, а не только её узел. В тестах это значит ждать разрешения ПЕРЕД
первым чтением разметки, даже если проверяете соседний текст.

## Посмотреть живьём

Кит по умолчанию не несёт ни одного стиля: размер и цвет приезжают формой скина (либо наследуются
от текста, как в проверочном рецепте). Смотреть живьём — на dev-сервере приложения, где кит
подключён вместе со скином.

Правила формы для иконки пишутся на её адрес (`[data-scope="icon"][data-part="root"]`) без ветки
вида: ось вида в паспорте объявлена, но донести имя вида до разметки сегодня нечем — `IconProps`
принимает только `name`. Форма, написанная «под вариант», на иконке просто не совпадёт.

Полный рабочий прогон — тесты компонента; отдельный гейт `test/shipped-artifact.test.ts` проверяет
СОБРАННЫЙ `dist`: каждое имя словаря обязано резолвиться снаружи кита, тем же путём, каким это
сделает потребитель. Две прежние реализации резолва были зелёными в тестах и ломались вне их —
поэтому гейт смотрит на поставку, а не на исходники.
