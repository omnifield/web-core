# 🧭 Toc

<h2 id="главное">🏠 Главное</h2>

🏷️ other · 🧬 component · 📐 regular · 📦 `@web-core/ui`

Список ссылок на заголовки страницы 🧭, который сам следит, какой заголовок сейчас на виду, и
подсвечивает его в списке. Кит не рисует скроллируемый контент сам — только следит за настоящими
заголовками, которые дал потребитель, и подсказывает список ссылок на них.

<h2 id="анатомия">🧩 Анатомия</h2>

Две независимые ветки под одним корнем: `content` — настоящий контент со своими заголовками,
`nav` — список-навигация, который эти заголовки отслеживает. 🧭

```
root
├─ content
└─ nav
   ├─ title 🏷️
   └─ list
      ├─ indicator •
      └─ item[] 🔘
         └─ link
```

| часть          | значение                                                                 | принимает внутри     | рисуется       |
| --------------- | ------------------------------------------------------------------------- | ---------------------- | -------------------- |
| 🧭 `root`      | оглавление целиком — держит список заголовков и знает, какой сейчас виден  | `content`, `nav`       | `Toc`             |
| 📄 `content`   | настоящий скроллируемый контент со своими заголовками — оглавление отслеживает ИХ, а не рисует само | текст, любой компонент | `TocContent`  |
| ➖ `nav`       | боковая панель навигации — оборачивает подпись панели и сам список ссылок  | `title`, `list`        | `TocNav`          |
| 🏷️ `title`    | подпись панели — например, «На этой странице»                             | текст                  | `TocTitle`        |
| ➖ `list`      | список ссылок на заголовки                                                 | `indicator`, `item`     | `TocList`         |
| • `indicator`  | скользящий указатель под активной ссылкой — своего графика не несёт        | —                      | `TocIndicator`    |
| 🔘 `item`      | один пункт списка — оборачивает ссылку на один заголовок                   | `link`                 | `TocItem`         |
| `link`         | сама ссылка — клик скроллит к заголовку вместо обычного перехода            | текст                  | `TocLink`         |

> [!NOTE]
> `content`/`nav` не существуют в анатомии Zag вовсе — реальная композиция Ark отдаёт их как голые
> `<article>`/`<nav>`, без своего адреса. Кит придумал их сам (`.extendWith("content", "nav")`) и
> дал им настоящий `data-scope`/`data-part` — чтобы скин мог одеть панель навигации отдельно от
> самого контента, не только через голый тег снаружи.

<h2 id="использование">🚀 Использование</h2>

Настоящие заголовки живут в `content`, список ссылок на них — в `nav`; свести их вместе можно
вручную или по схеме. 🔗

**Ручная сборка** — компонент собирается вручную, JSX-композицией, без схемы и движка. Заголовки
внутри `content` — обычная разметка потребителя, оглавление лишь ищет их по `id`, совпадающему с
`value` из `items`.

```tsx
const items = [
  { value: "intro", depth: 2, label: "Введение", href: "#intro" },
  { value: "install", depth: 2, label: "Установка", href: "#install" },
];

<Toc items={items}>
  <TocContent>
    <h2 id="intro">Введение</h2>
    <p>…</p>
    <h2 id="install">Установка</h2>
    <p>…</p>
  </TocContent>

  <TocNav>
    <TocTitle>На этой странице</TocTitle>
    <TocList>
      <TocIndicator />
      {items.map((item) => (
        <TocItem item={item}>
          <TocLink href={item.href}>{item.label}</TocLink>
        </TocItem>
      ))}
    </TocList>
  </TocNav>
</Toc>;
```

**Рендер через движок** — та же композиция, но по схеме (сборка `basic`), которую рисует
`RenderTree`. `content` в сборке остаётся пустым слотом — заголовки кладёт тот, кто использует
компонент, схема их не выдумывает.

```tsx
const data = { items };
const tree = instanceOf("toc", {}, "basic", data);

<RenderTree tree={tree} registry={registry} data={data} />;
```

> [!NOTE]
> `scrollEl` — необязательный проп `Toc`: без него оглавление следит за всем документом
> (`getElementById` + `IntersectionObserver` на весь viewport), с ним — только за конкретным
> скроллируемым контейнером. Функция-ref не резолвится через данные схемы (`bind` резолвит только
> сериализуемые JSON-значения) — сборка `basic` его не трогает вовсе, сузить слежение до одного
> контейнера можно только ручной композицией.

<h2 id="состояния">🎛️ Состояния</h2>

|      | часть      | состояние | метка          | значение                                             |
| ---- | ----------- | ---------- | ---------------- | --------------------------------------------------------- |
| 👁️   | item, link  | active     | `[data-active]`    | заголовок этого пункта сейчас виден                        |
| ⬆️   | item        | first      | `[data-first]`     | этот пункт — первый среди видимых сейчас заголовков         |
| ⬇️   | item        | last       | `[data-last]`      | этот пункт — последний среди видимых сейчас заголовков      |

> [!NOTE]
> «Видимых сейчас» может быть НЕСКОЛЬКО заголовков одновременно (широкий `rootMargin`, короткие
> секции) — `first`/`last` про край ЭТОЙ группы, не про единственный активный пункт. `link` несёт
> тот же `active`, что и его `item` — плюс `aria-current="location"`, которого у `item` нет.

<h2 id="io">🔌 IO</h2>

Собранному по схеме оглавлению нужен список заголовков — сам список ничего не диспатчит через
схему, клик по ссылке ведёт настоящий скролл машины Zag, не событие наружу.

<h3 id="io-вход">📥 Вход</h3>

```json
{
  "items": [{ "value": "string", "depth": "number", "label": "string", "href": "string" }]
}
```

<h3 id="io-выход">📤 Выход</h3>

Ничего — оглавление не диспатчит события через схему, переход по ссылке ведёт настоящий клик и
настоящий скролл.

<h2 id="сборки">🏗️ Сборки</h2>

<h3 id="сборка-basic">🧱 basic</h3>

Заголовки из данных ведут список ссылок; сам контент — пустой слот, его наполняет потребитель.

```
root
  content[]
  nav
    title 🏷️ · text: "На этой странице"
    list
      indicator •
      item[] 🔘  · repeat: /items · bind: item
        link      · bind: href · text: {label}
```

<h2 id="рецепт">🎨 Рецепт</h2>

`indicator`'s `--left`/`--top`/`--width`/`--height` измеряет и пишет машина Zag — но НЕ на сам
`indicator`, а на `root` (в отличие от табов/радио-группы, где эти же переменные стоят на самом
указателе). Рецепт читает их через `ancestors`, называя `root` явно — обычное CSS-наследование
донесло бы значение само, но проверка скина не берёт это на веру без явной записи.

`item`'s `--depth` — уровень вложенности заголовка из данных, отступ `item` считает от него
(`calc((var(--depth) - 2) * var(--space-3))`, `2` — потому что `h2` самый частый верхний уровень).

`content` — `display: contents`: чистая обёртка, не участвует в раскладке сама, весь вид отдаёт
настоящему содержимому потребителя.

<h2 id="доступность">♿ Доступность</h2>

`link` — настоящий `<a href="#…">`: обычная навигация по ссылке работает всегда (открыть в новой
вкладке, скопировать адрес), клик по ней в этой же вкладке подменяется на плавный скролл. Активная
ссылка несёт `aria-current="location"` — то же самое сообщает `[data-active]` визуально.
