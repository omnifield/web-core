# 🌱 `rootless` — реактивные корни, которые кто-то гасит

Взятый примитив комьюнити. Здесь его полный разбор: что даёт, как звать, где грабли. Короткая
вводка и место среди остального — [`EXAMPLES.md`](../EXAMPLES.md), раздел «Примитивы».

## 🎯 Зачем он вообще

У `createRoot` из самого Solid есть ручка `dispose`, и на этом помощь заканчивается: **кто и когда
её дёрнет — забота вызывающего.** Пока корней единицы, дисциплины хватает. Как только корни
создаются по данным — на ключ, на набор аргументов, на строку списка, — дисциплина перестаёт
работать: корней столько, сколько было разных входов за всю жизнь страницы, и не гаснет ни один.

Признак, что нужен именно этот подпуть: **`createRoot` вызывается внутри кэша или фабрики**, а не
один раз на старте приложения. Течёт это молча — ни ошибки, ни предупреждения, только растущая
память и эффекты, которые продолжают считать для давно не нужных данных.

Пакет закрывает три разных ответа на «кто гасит»:

| Ответ | Чем | Корень живёт, пока |
| --- | --- | --- |
| Гасит **владелец** | `createSubRoot` | жив родительский владелец |
| Гасят **потребители**, все вместе | `createSingletonRoot` | есть хоть один слушатель |
| Гасит **лимит**, с переиспользованием | `createRootPool` | не вытеснен из пула |

## 📦 Состав подпути

Шесть функций плюс два устаревших псевдонима — реэкспорт вендора один в один.

| Экспорт | Сигнатура | Про что |
| --- | --- | --- |
| `createSubRoot` | `(fn: (dispose) => T, ...owners) => T` | корень, гаснущий вместе с владельцем |
| `createSingletonRoot` | `(factory: (dispose) => T, detachedOwner?) => () => T` | один общий корень на всех, со счётчиком слушателей |
| `createRootPool` | `(factory, options?) => (arg) => TResult` | пул корней с лимитом и переиспользованием |
| `createDisposable` | `(fn: (dispose) => void, ...owners) => VoidFunction` | `createSubRoot`, отдающий только ручку |
| `createCallback` | `(callback: T, owner?) => T` | обёртка `runWithOwner` для колбэка |
| `createHydratableSingletonRoot` | `(factory) => () => T` | ⚠️ экспериментальный: синглтон, разъезжающийся на SSR и гидрации |
| `createBranch` | — | ⛔ устаревший псевдоним `createSubRoot` |
| `createSharedRoot` | — | ⛔ устаревший псевдоним `createSingletonRoot` |

Два последних вендор держит ради совместимости со своими старыми выпусками. В новом коде они не
используются; почему они всё-таки видны из подпути — [`FAQ.md`](../FAQ.md).

## `createSingletonRoot` — главная функция подпути

Начинка строится при **первом** обращении, переиспользуется всеми следующими и уничтожается, когда
уходит **последний** слушатель. Пришёл новый — строится заново.

```ts
import { createMemo, createSignal } from "@web-core/solid";
import { createSingletonRoot } from "@web-core/solid/rootless";

const useConnection = createSingletonRoot(() => {
  const [status, setStatus] = createSignal("idle");
  const socket = openSocket(setStatus);
  onCleanup(() => socket.close());
  return { status, ready: createMemo(() => status() === "open") };
});

// В любом компоненте — сколько угодно раз, соединение одно:
const { ready } = useConnection();
```

Как считаются слушатели: **вызов регистрирует текущего реактивного владельца**, а не «пользователя»
в каком-то своём смысле. Поэтому звать его нужно внутри компонента или другого владельца — вызов из
голого модульного кода не будет посчитан ничьим и корень не погаснет никогда.

**Гашение отложено на микротаск, и это важное свойство, а не деталь реализации.** Между уходом
последнего слушателя и уничтожением корня есть окно: если в том же тике появился новый слушатель,
переиспользуется прежняя начинка. Именно поэтому переключение между двумя компонентами, которые оба
зовут один синглтон, не пересоздаёт соединение на каждый щелчок. Проверено прогоном
(`test/rootless.test.tsx`): счётчик построений остаётся `1`.

| Что произошло | Что с корнем |
| --- | --- |
| Первый вызов | построен |
| Второй, третий, … | переиспользован, `factory` не зовётся |
| Ушёл не последний слушатель | жив |
| Ушёл последний, в том же тике пришёл новый | жив, начинка та же |
| Ушёл последний, тик закончился | уничтожен, `onCleanup` внутри сработал |
| Пришёл слушатель после уничтожения | построен заново |

Второй аргумент (`detachedOwner`) отвечает на вопрос, к кому корень прицеплен сверху; по умолчанию
— владелец, действовавший в момент **создания** синглтона, а не в момент первого вызова.

## `createSubRoot` — корень, гаснущий с владельцем

Когда корень нужен не общий, а свой, но отпускать его руками не хочется:

```ts
import { createEffect, onCleanup } from "@web-core/solid";
import { createSubRoot } from "@web-core/solid/rootless";

createSubRoot(() => {
  createEffect(() => watch(source()));
  onCleanup(() => detach());
});
// Владелец умер — этот корень уничтожен вместе с ним.
```

Ручка отдаётся телу первым аргументом — можно погасить раньше владельца:

```ts
const stop = createSubRoot<() => void>((dispose) => {
  createEffect(() => poll());
  return dispose;
});

stop(); // корень уничтожен сейчас, владельца ждать не стали
```

Владельцев можно назвать несколько — `createSubRoot(fn, ownerA, ownerB)`. Тогда корень гаснет, как
только умирает **любой** из них, а не последний: он подписывается на очистку каждого.

`createDisposable` — тот же `createSubRoot`, когда из тела не нужно ничего, кроме ручки:

```ts
const stop = createDisposable(() => {
  createEffect(() => poll());
});
```

## `createRootPool` — когда корни создаются и гаснут часто

Третий ответ на «кто гасит»: никто не гасит, корни **переиспользуются**. Подходит для того, что
монтируется и размонтируется потоком — строки виртуального списка, всплывающие карточки.

```tsx
import { createRootPool } from "@web-core/solid/rootless";

const useRow = createRootPool(
  (arg, active) => {
    const [value, setValue] = createSignal(arg());
    createEffect(() => {
      if (!active()) return; // корень сейчас лежит в пуле, работать не надо
      report(value());
    });
    return <Row value={value()} />;
  },
  { limit: 50 },
);
```

Тело получает три вещи: `arg` — сигнал аргумента (при переиспользовании приезжает новый), `active`
— лежит ли корень сейчас в пуле, `dispose` — выкинуть корень из оборота насовсем. Лимит по
умолчанию **100**; лишние корни поверх лимита уничтожаются, а не копятся.

⚠️ Пул — это переиспользование **состояния**, а не только узлов: сигналы внутри переживают
переработку. Всё, что обязано начинаться с нуля на каждый заход, инициализируется от `arg`, а не
константой в теле.

## `createCallback` — владелец для кода, который зовут позже

Реактивный примитив, созданный в обработчике события или в колбэке таймера, оказывается без
владельца: Solid уже вышел из фазы установки, очищать созданное некому.

```ts
import { createCallback } from "@web-core/solid/rootless";

const handleClick = createCallback(() => {
  createEffect(() => track(selection()));
});
// Позже, из DOM-обработчика:
handleClick(); // эффект принадлежит компоненту и умрёт вместе с ним
```

Это тонкая обёртка над `runWithOwner`, а не новый корень: владелец берётся тот, что действовал в
момент **создания** обёртки. Нет владельца вовсе — колбэк возвращается как есть, без обёртки.

## 🪤 Грабли

- **Синглтон, вызванный вне владельца, не гаснет никогда.** Счётчик слушателей растёт по
  зарегистрированным владельцам; вызов из модульного кода не регистрирует никого, и корень остаётся
  жить до конца страницы. Проверять надо не «вызвался ли», а «внутри чего вызвался».
- **Уничтожение не синхронное.** Сразу после ухода последнего слушателя `onCleanup` внутри корня
  ещё не сработал — он сработает после микротаска. В тесте это ожидание (`await Promise.resolve()`),
  в коде — повод не полагаться на порядок между гашением корня и тем, что идёт следом в том же тике.
- **`createSubRoot` с несколькими владельцами гаснет по первому, а не по последнему.** Список
  владельцев — это «умер любой», а не «умерли все». Нужна вторая семантика — это `createSingletonRoot`.
- **Пул переиспользует состояние.** Корень из `createRootPool` приходит с прежними сигналами внутри;
  всё, что должно быть чистым, инициализируется от `arg`.
- **`createHydratableSingletonRoot` вендор сам помечает экспериментальным** — на SSR и гидрации он
  намеренно перестаёт быть синглтоном. Без SSR брать его незачем.
