# 🧪 Примеры — как работать с `@web-core/solid`

Рабочий код, который можно скопировать и сразу погонять. Устройство и решения —
[`README.md`](./README.md) / [`FAQ.md`](./FAQ.md), план — [`ROADMAP.yaml`](./ROADMAP.yaml).

Всё, что ниже, прогнано на коде пакета 2026-09-19.

**Главное деление, из-за которого стоит прочитать словарь первым.** В пакете лежат две разные
вещи, и путать их дорого:

- **Движок** — сам Solid, доехавший сюда без изменений, плюс одно наше добавление (`mountApp`).
  Берёшь его потому, что зонам кита запрещено импортировать `solid-js` напрямую. Он весь здесь,
  кейсы 1–4;
- **Примитивы** — механики, которых у Solid нет, взятые готовыми у комьюнити. У каждого **свой
  разбор** в папке [`PRIMITIVES/`](./PRIMITIVES), здесь только вывеска: что это и куда идти. Не
  взятое — в [бэклоге](./PRIMITIVES/BACKLOG.md), и из пакета оно не импортируется.

<h2 id="словарь">0. Пять подпутей и что за каждым</h2>

Подпуть называет **происхождение** кода — по спецификатору импорта видно, чья это вещь и кто её
чинит.

| Подпуть | Род | Что внутри | Кто сопровождает |
| --- | --- | --- | --- |
| `@web-core/solid` | движок | весь `solid-js` как есть | команда Solid |
| `@web-core/solid/web` | движок | весь `solid-js/web` как есть | команда Solid |
| `@web-core/solid/mount` | наше | `mountApp(root)` — точки входа у Solid нет вовсе | этот пакет |
| `@web-core/solid/keyed` | примитив | весь `@solid-primitives/keyed` | `solidjs-community` |
| `@web-core/solid/rootless` | примитив | весь `@solid-primitives/rootless` | `solidjs-community` |

Правило одной строкой: **зона кита импортирует отсюда, а не из `solid-js`**. Тогда во всех файлах
резолвится один и тот же физический модуль, а версию решают в одном месте, а не в двадцати
`package.json`. Почему так — [`FAQ.md`](./FAQ.md).

<h2 id="кейс-1">1. Точка входа приложения: `mountApp()`</h2>

Единственное место, где это вообще зовётся, — `main.tsx` приложения. Один раз за жизнь проекта.

```tsx
// src/main.tsx
import { mountApp } from "@web-core/solid/mount";

import { App } from "./app";

mountApp(() => <App />);
```

```html
<!-- index.html -->
<div id="root"></div>
```

Три вещи, которые обычно спрашивают:

- **точку монтирования функция ищет сама** — идентификатор не аргумент, поэтому разметку страницы
  можно двигать, не трогая `main.tsx`;
- **наружу не возвращается ничего** (`void`). Ручку уничтожения корня функция держит у себя, по
  узлу-хозяину — отдавать её некому и незачем;
- **нет `#root` — летит `Error` с текстом, что добавить**, а не тихий пустой экран.

Реальный корень приложения обычно обёрнут провайдерами — они монтируются тут же:

```tsx
import { mountApp } from "@web-core/solid/mount";
import { QueryClient, QueryClientProvider } from "@web-core/query";
import { RouterProvider } from "@web-core/router";

import { router } from "./router";

const queryClient = new QueryClient();

mountApp(() => (
  <QueryClientProvider client={queryClient}>
    <RouterProvider router={router} />
  </QueryClientProvider>
));
```

<h2 id="кейс-2">2. Реактивное ядро через фасад</h2>

Импорт один в один с `solid-js`, меняется только спецификатор. Ничего заворачивать не надо —
`createSignal` здесь это тот самый `createSignal`.

```tsx
import { createEffect, createMemo, createSignal, onCleanup, onMount } from "@web-core/solid";

export function Ticker() {
  const [ticks, setTicks] = createSignal(0);
  const label = createMemo(() => (ticks() % 2 === 0 ? "чёт" : "нечет"));

  onMount(() => {
    const id = setInterval(() => setTicks((n) => n + 1), 1000);
    onCleanup(() => clearInterval(id));
  });

  createEffect(() => console.log("тик", ticks(), label()));

  return <span>{ticks()} — {label()}</span>;
}
```

Что отсюда доступно: всё, что есть у `solid-js`, — `createResource`, `createContext`/`useContext`,
`batch`, `untrack`, `For`, `Index`, `Show`, `Switch`/`Match`, `ErrorBoundary`, `Suspense`,
`createUniqueId`, JSX-типы. Реэкспорт полный намеренно: отбор по имени значил бы забыть прокинуть
новое при очередном выпуске Solid.

<h2 id="кейс-3">3. Рендер руками: `render` и `Portal`</h2>

`mountApp()` закрывает обычный случай. Голый `render` нужен, когда корней несколько или хозяина
выбираешь не ты: виджет на чужой странице, стенд, проба в тесте.

```tsx
import { render } from "@web-core/solid/web";

const host = document.querySelector("#widget-slot")!;
const dispose = render(() => <Widget />, host);

// Корень обязан быть уничтожен явно, иначе его вычисления живут дальше.
window.addEventListener("beforeunload", dispose);
```

`Portal` — когда узел обязан оказаться вне своего родителя по DOM, а по реактивности остаться
внутри (модалка, тултип, дроп поверх `overflow: hidden`):

```tsx
import { Show, type JSX } from "@web-core/solid";
import { Portal } from "@web-core/solid/web";

export function Modal(props: { open: boolean; children: JSX.Element }) {
  return (
    <Show when={props.open}>
      <Portal mount={document.body}>
        <div class="backdrop">{props.children}</div>
      </Portal>
    </Show>
  );
}
```

<h2 id="кейс-4">4. Второй `mountApp()` на том же `#root` — HMR и рестарт</h2>

Повторный вызов на том же элементе — это не ошибка и не «второе приложение». Прежний корень
**гасится до** нового рендера:

```tsx
mountApp(() => <span>первый</span>);   // #root: «первый»
mountApp(() => <span>второй</span>);   // #root: «второй», первый корень уничтожен
```

Проверено прогоном: содержимое `#root` заменяется целиком, а компонент первого корня заново не
вызывается — он снят, а не спрятан.

Инвариант простой: **один документ — одно приложение**. Если бы корни складывались стопкой, старые
эффекты продолжали бы реагировать на изменения, до которых новый UI уже не имеет отношения, —
именно так выглядит «после хот-релоада всё стало тормозить и дублировать запросы».

<h2 id="кейс-5">5. Что взято и где про это читать</h2>

Примитивы разбираются не здесь: у каждого свой файл в [`PRIMITIVES/`](./PRIMITIVES) — там паспорт
(вендор, версия, чем подтверждено), полный состав экспортов, примеры и грабли. Ниже — только
вывеска, чтобы понять, туда ли идти.

| Примитив | Адрес импорта | Про что в одну строку | Разбор |
| --- | --- | --- | --- |
| `keyed` | `@web-core/solid/keyed` | `<Key each by>` и родня: список, где узел держится за **названный ключ**, а не за ссылку на объект (`<For>`) и не за позицию (`<Index>`). Плюс обход объекта/`Map`/`Set` и `<Rerun>` | [`keyed.md`](./PRIMITIVES/keyed.md) |
| `rootless` | `@web-core/solid/rootless` | реактивные корни, которые **кто-то гасит**: общий на всех со счётчиком слушателей (`createSingletonRoot`), гаснущий с владельцем (`createSubRoot`), вытесняемый по лимиту (`createRootPool`) | [`rootless.md`](./PRIMITIVES/rootless.md) |

Признак, что тебе сюда: **после обновления списка слетает фокус или выделение**, хотя данные почти
те же — значит `<For>` не узнал элементы, потому что объекты приехали новые.

```tsx
import { Key } from "@web-core/solid/keyed";

<Key each={props.items} by={props.itemKey}>
  {(item) => <Node value={props.itemKey(item())} />}
</Key>;
```

⚠️ **Взято пока ровно два.** Всё остальное из экосистемы — в [бэклоге](./PRIMITIVES/BACKLOG.md):
это очередь, а не поставка, и импортировать оттуда нечего. Нужен следующий — заявка архитектору,
а не `pnpm add` в своей зоне.

<h2 id="кейс-6">6. «Реактивность не работает» — почти всегда условия резолва</h2>

Симптом: в тесте или в ноде компонент рендерится один раз и больше не обновляется, сигналы вроде бы
меняются, а DOM стоит. Причина не в коде — `solid-js/web` отдаёт **серверную** сборку, если условия
резолва не названы: там рендер разовый по определению.

Лечится в конфиге прогона, а не в компоненте:

```ts
// vitest.config.ts
import solid from "vite-plugin-solid";
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    projects: [
      {
        plugins: [solid()],
        resolve: { conditions: ["development", "browser"] },
        test: {
          environment: "jsdom",
          include: ["test/*.test.tsx"],
        },
      },
    ],
  },
});
```

Ровно этот конфиг лежит в пакете — с него можно списывать. Вторая частая причина того же симптома —
**деструктуризация**: тело `<Key>`/`<For>` отдаёт сигнал, и `const { title } = item()` читает
значение один раз, навсегда. Читать надо в том месте, где значение используется.

<h2 id="кейс-7">7. Чего здесь нет и где это искать</h2>

- **`Key` нет в барели `@web-core/solid`** — и не будет: барель дословно зеркалит `solid-js`, а
  `Key` не оттуда. Импорт из `./keyed`, всегда.
- **Прямой `import … from "solid-js"` в зоне кита — не «тоже вариант», а то, ради отмены чего
  пакет существует.** Сегодня часть зон так ещё импортирует; это известный долг
  (`ROADMAP.yaml`, `id: migrate-direct-solid-imports`), а не образец.
- **Остальные примитивы комьюнити НЕ подключены** — [`PRIMITIVES/BACKLOG.md`](./PRIMITIVES/BACKLOG.md)
  описывает то, что мы могли бы взять, а не то, что есть.
- **Роутинг, запросы, стор, стили** — отдельные пакеты кита (`@web-core/router`, `@web-core/query`,
  `@web-core/store`, `@web-core/style`). Здесь только сам Solid и то, что достроено вокруг него.
