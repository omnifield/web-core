# Что нужно от бэкенда

Документ для backend-команды. Фронт собран на движковом фреймворке: экраны — это не свёрстанные
вручную страницы, а **модули**, собранные из готовых компонентов и описанные данными. Для вас это
почти ничего не меняет, и вот главное сообщение:

> **Фронту нужен обычный REST + JSON. Никаких специальных форматов, никакого рендеринга на
> сервере, никакого знания о компонентах и стилях.**

Дальше — минимум, который стоит знать, чтобы стык прошёл без переделок.

---

## 1. Формат данных — ваш, не наш

Компонент таблицы (как и любой другой) умеет работать только со своей формой данных. Но
**подгонять ответ под неё вы не должны**: между вашей ручкой и компонентом на фронте стоит
адаптер — перекладка ключей и значений, которая настраивается мышью, без кода.

Ваш ответ:

```json
{
  "data": {
    "items": [
      { "client_name": " Ада ", "date": "04.09.2026", "total": "1 234,5" },
      { "client_name": "Марк", "date": "05.09.2026", "total": "10" }
    ],
    "total_count": 2
  }
}
```

Форма, которую ждёт компонент:

```json
[
  { "customer": "Ада", "placedAt": "2026-09-04T00:00:00.000Z", "amount": 1234.5 },
  { "customer": "Марк", "placedAt": "2026-09-05T00:00:00.000Z", "amount": 10 }
]
```

Переименование полей, обрезка пробелов, разбор даты `дд.мм.гггг`, число из строки с пробелом и
запятой — всё это делает адаптер на фронте. **Вам достаточно отдавать то, что у вас уже есть.**

Что реально помогает (но не обязательно):

- стабильные имена полей — переименование поля в ответе ломает настроенный адаптер;
- явные типы: число числом, а не строкой, дата в ISO-8601 — тогда адаптер проще и надёжнее;
- если записей много — отдавайте их массивом в предсказуемом месте ответа (`data.items`, `content`,
  `rows` — любое, лишь бы не меняющееся от ручки к ручке).

## 2. Ручки данных

Обычный контроллер. Ничего особенного:

```java
@RestController
@RequestMapping("/api/orders")
public class OrderController {

    private final OrderService orders;

    public OrderController(OrderService orders) {
        this.orders = orders;
    }

    @GetMapping
    public OrderPage list(
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "20") int size,
            @RequestParam(required = false) String status) {
        return orders.find(page, size, status);
    }

    @GetMapping("/{id}")
    public OrderDto one(@PathVariable long id) {
        return orders.byId(id);
    }
}
```

DTO — обычные:

```java
public record OrderDto(
        long id,
        String clientName,
        Instant placedAt,
        BigDecimal total,
        String status) {}

public record OrderPage(List<OrderDto> items, long totalCount) {}
```

**Как фронт передаёт параметры.** Имя параметра, встреченное в фигурных скобках адреса
(`/api/orders/{id}`), уходит в путь; параметр с именем `body` — в JSON-тело; всё остальное — в
query-строку. То есть `GET /api/orders?page=0&size=20&status=NEW` — ровно то, что вы и ожидаете.

## 3. Два обязательных технических момента

### CORS

Фронт живёт на другом домене, поэтому браузер сначала спросит разрешение. Без этого не поедет
ничего, и это самая частая причина «у вас всё сломано» в первый день.

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("https://demo.example.com")
                .allowedMethods("GET", "POST", "PUT", "DELETE")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
```

Конкретный origin, а не `*`, — иначе `allowCredentials` работать не будет.

### Авторизация

Обычный `Authorization: Bearer <token>`. Фронт умеет подставлять заголовок ко всем вызовам —
своего механизма аутентификации он не приносит и не навязывает. Если у вас сессия на куках —
тоже подойдёт, тогда важен `allowCredentials` выше и правильный `SameSite`.

## 4. Ошибки

Не-2xx — **нормальный ответ**, а не авария: фронт его разберёт и покажет. Важно только, чтобы у
ошибки была предсказуемая форма, одна на все ручки:

```json
{
  "error": "ORDER_NOT_FOUND",
  "message": "Заказ 42 не найден",
  "field": null
}
```

```java
@ExceptionHandler(OrderNotFound.class)
public ResponseEntity<ApiError> notFound(OrderNotFound e) {
    return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ApiError("ORDER_NOT_FOUND", e.getMessage(), null));
}
```

`error` — машинный код (по нему фронт решает, что делать), `message` — текст человеку,
`field` — имя поля, если ошибка относится к конкретному полю формы.

## 5. Управление интерфейсом с бэка — опционально

Это не обязательно для первого запуска, но именно здесь фреймворк даёт то, чего обычно нет.

Фронт умеет **гасить и прятать куски интерфейса по внешнему правилу**. Например, кнопку «Удалить»
не нужно показывать тому, у кого нет права удалять. Защита при этом остаётся на вас — бэк и так не
выполнит запрещённую операцию, — но кнопка в интерфейсе лишняя, и решает это бэк, а не фронт.

Ручка вида:

```java
@GetMapping("/api/ui/permissions")
public Map<String, Boolean> permissions(Authentication auth) {
    return Map.of(
            "order.delete", hasRole(auth, "ORDER_ADMIN"),
            "order.edit",   hasRole(auth, "ORDER_EDITOR"),
            "report.export", hasRole(auth, "ANALYST"));
}
```

```json
{ "order.delete": false, "order.edit": true, "report.export": true }
```

Фронт сопоставляет эти ключи с узлами интерфейса и прячет либо блокирует их. **Ключи придумываете
вы** — это ваши права, не наши имена компонентов. Единственное требование — они должны быть
стабильными.

То же самое работает для правил валидации, если вы хотите держать их на сервере: «поле
обязательно», «значение не подходит, вот текст ошибки». Формат обсуждается отдельно, когда до
этого дойдёт.

## 6. Чего делать НЕ надо

- **Не рендерить HTML.** Сервер отдаёт данные, страницу собирает браузер.
- **Не подстраивать JSON под компоненты.** Для этого есть адаптер, и он меняется без релиза бэка.
- **Не отдавать вёрстку, стили и тексты интерфейса.** Вид — целиком зона фронта.
- **Не делать «ручку на экран».** Одна ручка — одна сущность; из чего состоит экран, решает фронт,
  и это меняется чаще, чем ваш API.

---

## 7. Чек-лист на первый стык

1. Ручка отдаёт JSON и доступна с домена фронта (CORS настроен на конкретный origin).
2. Массив записей лежит в предсказуемом месте ответа.
3. Ошибки — единой формы, с машинным кодом.
4. `Authorization: Bearer` принимается (или сессия на куках работает с `allowCredentials`).
5. Есть тестовый стенд, куда фронт может ходить, и учётка для него.

Этого достаточно, чтобы экран, собранный на фронте, ожил на ваших данных. Всё остальное —
перекладка полей, вид, состав экрана — настраивается на нашей стороне и релиза бэкенда не требует.
